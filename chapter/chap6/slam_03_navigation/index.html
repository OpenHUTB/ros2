6.3 导航功能包与实时避障

本节在已有二维栅格地图的基础上，实现机器人"在地图上定位 + 路径规划 + 自主导航 + 实时避障"。 与 6.1、6.2 的 Gazebo 物理仿真不同，本节使用 arbotix 假仿真：不启动 Gazebo 物理引擎，只用软件 模拟一台差速机器人的里程计与运动，配合 map_server + fake_localization + move_base 完成导航， 并支持 rviz 中的 2D Nav Goal 手动导航与 random_navigation 随机自动导航。

本节配套功能包位于仓库：

src/chap6/catkin_ws/src/mrobot_bringup/       # arbotix 假机器人启动配置（精简版）
src/chap6/catkin_ws/src/mrobot_description/   # 假仿真使用的简化 URDF 模型
src/chap6/catkin_ws/src/mrobot_navigation/    # move_base、fake_localization、代价地图、随机导航脚本

1. 本节目标

  1. 理解自主导航要解决的两大问题——定位与路径规划；
  2. 理解 move_base 的工作机制、全局/局部规划器与两层代价地图（costmap）；
  3. 理解 arbotix 假仿真与 fake_localization 的作用，理清完整的 TF 坐标树；
  4. 安装 navigation、arbotix 功能包；
  5. 准备精简版 mrobot_bringup、mrobot_description 并修复 Noetic 兼容问题；
  6. 用两个终端启动假机器人与导航，在 rviz 中用 2D Nav Goal 手动导航；
  7. 运行 random_navigation 随机自动导航，并分析 Python3 下的字典采样报错与修复。

2. 背景知识

2.1 自主导航的两大问题

移动机器人在一张已知地图上自主走到目标点，需要回答两个问题：

  1. 我在哪里（定位，Localization）：确定机器人当前在地图坐标系中的位姿（位置 x、y 与朝向 yaw）；
  2. 我该怎么去（路径规划，Planning）：在地图上找到一条从当前位姿到目标点、不与障碍物碰撞的路径， 并把它转换成电机可执行的速度指令。

真实机器人通常用 AMCL（自适应蒙特卡洛定位） 解决第一个问题，用 move_base 解决第二个问题。 本节的假仿真用 fake_localization 代替 AMCL，获得"完美定位"，以便把注意力集中在导航框架本身。

2.2 move_base 与两大规划器

move_base 是 ROS 导航栈的核心节点，它对外提供一个 move_base 的 action 接口 （MoveBaseAction）：客户端只需下发一个目标位姿，move_base 就会负责规划并执行，期间反馈状态、 完成后返回结果。其内部主要包含两个规划器：

规划器 作用 本节实现
全局规划器（Global Planner） 在整张地图上做全局寻路，生成从当前点到目标点的全局路径 navfn/global_planner（Dijkstra/A* 类算法）
局部规划器（Local Planner） 在机器人附近滚动地采样速度、预测短轨迹，输出实时 cmd_vel，并负责避障 base_local_planner 的 TrajectoryPlannerROS（DWA 思路）

执行时，局部规划器以全局路径为引导，结合周围障碍物持续生成速度指令；若局部规划器发现无路可走， 可触发恢复行为（如清障、原地旋转）。本节配置 recovery_behavior_enabled: false，关闭了恢复行为。

2.3 代价地图 costmap

move_base 维护两张代价地图（Costmap2D），把不同来源的信息叠加成每个格子的"代价值"：

  • 全局代价地图（global_costmap）：覆盖整张地图，分辨率 0.01 m，长期稳定，供全局规划使用；
  • 局部代价地图（local_costmap）：只覆盖机器人周围 6 m × 6 m 的窗口，随机器人滚动更新，供局部规划使用。

代价地图采用分层（layer）结构，从下到上依次叠加：

  1. 静态层（static_layer）：直接加载 map_server 提供的静态地图，墙体等固定障碍来自这里；
  2. 障碍层（obstacle_layer）：根据实时传感器（/scan）标记/清除动态障碍；
  3. 膨胀层（inflation_layer）：在障碍物周围按机器人半径膨胀出一圈缓冲，避免机器人贴墙、刮蹭。

本节的假仿真方案不发布真实的 /scan 话题（简化 URDF 中激光雷达只有外形、没有 Gazebo 激光插件）， 因此障碍层没有实时数据，代价地图主要依赖静态地图。rviz 中 LaserScan 项无数据，但不会报错。

2.4 arbotix 假仿真与 fake_localization

arbotix 假仿真由 arbotix_python/arbotix_driver 提供，启动时设置 sim:=true：

  • 它用软件模拟一个差速控制器（diff_controller），订阅 cmd_vel，按 base_width、ticks_meter 等参数对速度积分，计算出假的里程计，发布 /odom 话题与 odom → base_footprint 的 TF，同时发布关节状态；
  • 整个过程不启动 Gazebo、不做物理碰撞计算，也不真正打开串口（配置里的 port: /dev/ttyUSB0 在 sim 模式下仅作占位），因此几乎不消耗物理算力，"假仿真"由此得名。

fake_localization（假定位）用来代替真实的 AMCL：

  • 它订阅里程计，把 odom 中的位姿直接包装成 AMCL 风格的 /amcl_pose 与 /particlecloud（粒子云）；
  • 它不做任何概率估计，默认里程计位姿就是真实位姿，因此是"完美定位"，不存在定位误差和粒子发散。

2.5 TF 坐标树

定位与导航都依赖一条完整、无冲突的 TF 坐标树。本节各节点共同维护的坐标关系如下：

map
 └── odom                 static_transform_publisher（map→odom 恒等变换）
      └── base_footprint  arbotix 的 diff_controller（假里程计）
           └── base_link  robot_state_publisher（依据 URDF）
                └── ... 电机、轮、板件 ...
                     └── laser_link
  • map → odom：由 static_transform_publisher 发布为零平移、零旋转的恒等变换；
  • odom → base_footprint：由 arbotix 假控制器随运动持续发布；
  • base_footprint → base_link → ... → laser_link：由 robot_state_publisher 解析 URDF 静态发布。

10.1 Python3 字典采样报错

首次运行时，脚本在随机选点阶段抛出异常：

Traceback (most recent call last):
  File ".../random_navigation.py", line 167, in <module>
    NavTest()
  File ".../random_navigation.py", line 76, in __init__
    sequence = sample(locations, n_locations)
  File "/usr/lib/python3.8/random.py", line 359, in sample
    raise TypeError("Population must be a sequence or set.  For dicts, use list(d).")
TypeError: Population must be a sequence or set.  For dicts, use list(d).
[INFO] Stopping the robot...

根因是 Python2 与 Python3 中 random.sample() 的行为差异：

  • 脚本里 locations 是一个字典（键是 p1~p6，值是目标位姿）；
  • Python2 的 sample 可以直接接受字典，对它的键采样；
  • Python3 的 sample 只接受序列（list/tuple）或集合（set），拒绝字典，并在报错中明确提示 For dicts, use list(d)。

10.2 修复并重新运行

按报错提示，把字典显式转成键列表再采样：

sed -i 's#sequence = sample(locations, n_locations)#sequence = sample(list(locations), n_locations)#' \
   ~/catkin_ws/src/mrobot_navigation/scripts/random_navigation.py

# 验证
grep -n 'sample' ~/catkin_ws/src/mrobot_navigation/scripts/random_navigation.py
python3 -m py_compile ~/catkin_ws/src/mrobot_navigation/scripts/random_navigation.py && echo "语法 OK"

list(locations) 返回字典所有键的列表，sample 对这些键随机排序，后续仍按键取出对应位姿， 逻辑完全兼容。重新运行后机器人开始随机选点导航，第 1 个目标点成功：

13. 离线检查地图与规划全局路径

前面的流程每次都要起 Gazebo + move_base 才能看一眼"这张图能不能走"。真机上更麻烦， 得把整套环境再拉起来。mrobot_navigation/scripts/map_planner.py 把其中两件事搬到离线： 地图体检和全局路径规划。

它只依赖 Python 标准库（PNG 也是用 zlib 手写的），Windows / macOS / Ubuntu 都能跑， 不需要 ROS、Gazebo 或 numpy。

13.1 它做了什么

  1. 读 map_saver 生成的 .pgm + .yaml（P5/P2，支持 negate 与两个阈值）；
  2. 按 occupied_thresh / free_thresh 分成 占用 / 自由 / 未知 三类；
  3. 统计自由/占用/未知比例，以及最大连通自由区——自由空间被噪点切成很多块时， 导航会"看得到、走不过去"；
  4. 按机器人半径做障碍膨胀（等价于 costmap 的 inflation_radius）；
  5. A* 规划全局路径，再做视线法平滑（只做几何捷径，曲率还是交给 local planner）；
  6. 输出一张叠加图：黑=墙、白=自由、灰=未知、浅红=膨胀区、蓝=路径。

13.2 用法

cd src/chap6/catkin_ws/src/mrobot_navigation

# 只体检地图
python3 scripts/map_planner.py --map maps/gmapping_map.yaml --stats

# 规划路径（坐标与 rviz 的 2D Nav Goal 一致，单位米）
python3 scripts/map_planner.py --map maps/gmapping_map.yaml \
    --start 1.15 5.46 --goal 9.77 5.17 --radius 0.18 --out plan.png

--radius 就是机器人的外接半径，和 costmap_common_params.yaml 里的 robot_radius 保持一致即可。

13.3 本章地图的实测结果

地图尺寸      : 512 × 544 px
物理范围      : 25.60 m × 27.20 m（分辨率 0.050 m/px）
自由 / 占用 / 未知 : 11.5% / 1.2% / 87.4%
最大连通自由区: 97.7%（占自由空间）
可通行面积    : 7.1%（半径 0.18 m 膨胀后，膨胀前 11.5%）

A* 路径点数   : 183
A* 路径长度   : 10.59 m
平滑后点数    : 6（长度 9.96 m）
直线距离      : 8.62 m（绕行系数 1.15）

三点解读：

  • 未知占 87.4% 很正常——map_saver 会按地图尺寸铺满初始化，机器人没走到的地方就是未知；
  • 最大连通自由区 97.7% 说明这张图的可通行区域基本连成一片，没有被激光噪点切碎；
  • 绕行系数 1.15 表示路径比直线多走 15%，属于走廊里正常绕行，不是原地打转。

图中绿色是起点、红色是终点、蓝色是平滑后的全局路径；浅红色区域是膨胀后的"机器人中心禁区"， 路径始终走在白色自由区里。
