# 实验协议

## 1. 目的

回答三个问题：

1. **分层神经方案（full）能否在五个场景（含留出场景）稳定到达目标？**
2. 与几何专家（expert）相比，神经方案在安全性、平滑性、计算量上如何？
3. 端到端（e2e）与分层方案相比，差距在哪里？

## 2. 对照组

| 组别 | 感知 | 规划 | 控制 | 说明 |
| --- | --- | --- | --- | --- |
| `expert` | 真值地图 | 经典 A\* | 几何专家 | 传统基线，代表“规则方法上限” |
| `control` | 真值地图 | 经典 A\* | **ControlNet** | 隔离控制网络，排除感知/规划误差 |
| `full` | **PerceptionNet** | **Neural A\*** | **ControlNet** | 完整分层神经链路 |
| `e2e` | **E2ENet**（深度直出） | — | — | 端到端对照 |

## 3. 变量控制

| 因素 | 设置 |
| --- | --- |
| 场景 | sparse / dense / dynamic / corridor（训练分布内）+ unseen（留出） |
| 随机种子 | 0, 1, 2（动态障碍相位、感知噪声、采样位姿） |
| 最大步数 | 650（65 s @10 Hz） |
| 控制限幅 | 1.2 m/s |
| 规划膨胀 | margin=2 格（1 m） |
| 重规划周期 | 每 10 步（1 s） |
| 到达容差 | 1.4 m |
| 碰撞阈值 | 0.32 m |
| 硬件 | 4 核 CPU / 16 GB，无 GPU |
| 软件 | Python 3.10（Windows）、3.8（Ubuntu 20.04 虚拟机） |

每个 (场景, 方法) 组合跑 3 个种子，共 \(5\times4\times3=60\) 回合。
统计时对种子取均值，成功率/碰撞率取比例。

### 3.1 训练/评测划分

| 场景 | 是否进入训练集 | 用途 |
| --- | --- | --- |
| sparse / dense / dynamic / corridor | 是（`collect.py` 写死） | **in-distribution** 主表 |
| unseen | **否** | **zero-shot** 泛化检查（§results 4.4） |

四个数据集（perception / planner / control / e2e）的场景列表都在
`ca_drone/data/collect.py` 中显式写为前四个名字，新增 `unseen` 不会自动泄漏进训练集；
`unseen` 也不参与调参。报告时把两者分开，避免把“在训练地图上 100%”说成泛化性能。

## 4. 指标定义

- **成功率**：`reached()` 为真且未碰撞；
- **碰撞率**：`clearance < 0.32 m` 或越界；
- **路径长度**：相邻位置距离累加，含绕行；
- **最小间隙**：全程到障碍表面的最小距离，越大越安全；
- **规划耗时**：单次 A\*（含神经场推理）的墙钟时间；
- **推理耗时**：单帧网络前向时间；
- **重规划次数**：在线地图触发 A\* 的次数，反映环境不确定性。

## 5. 复现命令

```bash
# 数据（可跳过，仓库外可再生成；约 15 s）
python tools/make_data.py --out data --e2e-episodes 60 --e2e-limit 14000

# 训练（默认轮数与随附权重一致：perception 4 / planner 12 / control 60 / e2e 12；
# 合计约 10 min，4 核 CPU）
python tools/train.py --module all --data data --weights weights

# 评测（60 回合，约 2 min）
python tools/evaluate.py --scenes all --modes expert,control,full,e2e \
    --seeds 3 --out results

# 图表
python tools/make_figs.py
```

## 6. 公平性说明

- 所有方法共享同一仿真器、同一动力学、同一目标与起点；
- `expert` 使用真值地图，是“开了天眼”的上界；
- `full` 只用深度图在线建图，感知误差会传播到规划与控制；
- `e2e` 不使用地图与规划，计算量最小；
- 时间指标为墙钟时间，受机器负载影响，表中同时给出相对大小。

!!! warning "关于仿真时间的说明"
    `duration_s` 是仿真时间（步数 × 0.1 s），不是墙钟时间。
    由于每步渲染与规划有开销，墙钟时间通常是仿真时间的 1/8–1/10；
    表格中的 `wall_s` 单独列出。

## 7. 失败判定

一个回合在以下任一情况结束：

1. 到达目标（成功）；
2. 与障碍距离 < 0.32 m（碰撞）；
3. 飞出世界边界（越界）；
4. 达到 650 步仍未到达（超时）。

后三者都记为失败；若同时发生，优先记碰撞。
