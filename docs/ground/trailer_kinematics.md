# 牵引车-挂车运动学与折刀判定（trailer_kinematics）

## 这一页解决什么问题

挂车不是「加长版单车」。它的航向是**第二个状态量**，由铰接点的横向速度驱动，
因此多出一个牵引车没有的现象：**折刀（trailer jackknife）**。倒车时这个状态还是
不稳定的——方向盘保持一个角度，铰接角就会一直涨到折刀。

这套东西在实车和仿真器里都很贵：要么开 CARLA 等世界跑起来，要么上路试。但它的核心
只是两个一阶微分方程加一个闭式解，完全可以在**离线、无图形界面、任何 Python 解释器**
上把「余量够不够」算清楚。

本模块因此定位成**挂车相关逻辑的回归护栏**：不产生画面、不需要 GPU、不订阅外部数据，
只吃参数、吐报告和字符图。

## 运动学模型

记牵引车后轴处航向为 θ₁、挂车航向为 θ₂、铰接角 φ = θ₁ − θ₂：

```
θ₁' = v · tan(δ) / L1
θ₂' = ( v·sin(φ) − d·θ₁'·cos(φ) ) / L2
```

| 符号 | 含义 | 本包默认 |
|---|---|---|
| L1 | 牵引车轴距 | 2.70 m |
| L2 | 铰接点到挂车轴 | 4.20 m |
| d | 铰接点在牵引车后轴后方的偏移（0 即「铰接在轴上」模型） | 0.60 m |
| δ | 前轮转角 | 25° |
| v | 速度（倒车取负） | 1.00 m/s |

积分方式是**显式欧拉**，步长默认 0.02 s。两个状态量每步都折算回 `[-π, π)`，
避免长时间仿真把角度累加成一圈以上。

## 稳态有闭式解，拿来当自检

令 φ' = 0，记 A = tan δ / L1，可得

```
sin(φ) − d·A·cos(φ) = L2·A
```

写成 R·sin(φ − ψ) = L2·A（R = √(1+(dA)²)、ψ = atan(dA)）后解出

```
φ_steady = atan(dA) + asin( L2·A / √(1 + (dA)²) )
```

- 默认参数：φ_steady ≈ **52.09°**
- 把 d 设成 0：退化为经典的 φ_steady = asin(L2·tan δ / L1) ≈ **46.50°**
- 当 L2·A/√(1+(dA)²) > 1 时**不存在稳态**，铰接角会一直涨到折刀

这个闭式解写进了离线测试（C 组），也写进了「30 秒长仿真是否收敛到 52.09°」这条
检查（C8）。积分代码一旦改坏，测试立刻红。

## 四条断言

| 断言 | 判据 | 为什么需要 |
|---|---|---|
| 折刀余量 | 最大铰接角 < 折刀角（默认 90°） | 折刀是这类车最致命的状态，必须留余量 |
| 积分精度 | 步长减半后位置差 ≤ `check/step_tolerance`（默认 1 cm） | 让「误差可忽略」这句话有据可依 |
| 通道宽度 | 全程车身角点横向跨度 ≤ `check/channel_width` | 决定这个弯能不能过 |
| 倒车稳定性 | 倒车时末段铰接角不得比首段大 1° 以上 | 倒车发散是物理事实，必须显式暴露 |

「通道宽度」的算法：把所有采样点上牵引车与挂车的 8 个角点投影到世界坐标，取 y 方向
（即起步时垂直于车身的方向）的跨度。默认 90° 转弯需要 **10.96 m**。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `trailer/wheelbase` | 2.70 | 牵引车轴距 (m) |
| `trailer/length` | 4.20 | 铰接点到挂车轴 (m) |
| `trailer/hitch_offset` | 0.60 | 铰接点在牵引车后轴后方 (m) |
| `trailer/max_steer_deg` | 35.0 | 前轮最大转角 (度) |
| `check/jackknife_deg` | 90.0 | 折刀角上限 (度) |
| `check/channel_width` | 12.00 | 允许占用的通道宽度 (m) |
| `check/step_tolerance` | 0.01 | 步长减半后的位置差上限 (m) |
| `sim/speed` | 1.00 | 行驶速度 (m/s) |
| `sim/steer_deg` | 25.0 | 前轮转角 (度) |
| `sim/seconds` | 9.10 | 仿真时长 (s)，默认正好转 90° |
| `sim/step` | 0.02 | 积分步长 (s) |
| `sim/gear` | 1 | 1 前进、-1 倒车 |
| `rate/publish_hz` | 10.0 | 报告发布后的保活频率 (Hz) |

命令行全部可覆盖，例如 `roslaunch trailer_kinematics main.launch steer_deg:=30.0`。

## 常见问题

**为什么默认跑 9.10 秒？**
L1 = 2.70 m、δ = 25° 时航向角速度是 0.1727 rad/s，转 90° 正好 9.10 s。这样一个默认
场景就是「路口转弯」，通道宽度这个指标才有意义。

**倒车为什么一定失败？**
不是代码坏了。倒车时铰接角的不动点是不稳定的，方向盘保持一个角度，铰接角就单调
增大到折刀。`gear:=-1` 存在的意义就是把这条写进证据里。

**为什么还要检查积分精度？**
显式欧拉在 0.02 s 下误差只有 7 mm，放大到 0.5 s 就变成 17.5 cm。这条断言让文档里
「误差可忽略」的说法有依据，也顺手抓「有人把步长调大图省事」这类回归。

**和 CARLA 的 scenario runner 什么关系？**
CARLA 的 scenario runner 管「整个世界怎么演」，需要仿真器；本模块只管挂车这一个
自由度的运动学和稳定性，任何 Python 都能跑，适合做挂车相关代码的回归护栏。

## TF 广播（ROS 原生形态）

节点算完轨迹后会持续广播变换（`tf/enabled` 默认 `true`，频率 `tf/rate_hz` 默认 10 Hz），
因此除了看终端报告，还可以用 ROS 自带的工具核对位姿：

```
$ rosrun tf tf_echo map tractor
$ rosrun tf view_frames     # 导出一份 tf 树到 frames.pdf
```

| parent | child | 含义 |
|---|---|---|
| `map` | `map -> tractor` | 牵引车后轴在全局地图里的位姿（轨迹终点状态） |
| `tractor` | `trailer` | 挂车轴在牵引车坐标系里的位姿（与报告里的铰接角一致） |

默认参数下 `map -> tractor` 的平移是 `(5.800, 5.785, 0.000)`、yaw 约 `1.5716 rad`；
`tractor -> trailer` 的平移是 `(-2.458, 2.879, 0.000)`。两张变换的相对航向
`-0.7552 rad` 正是 `trailer_yaw - tractor_yaw`，与报告中的 `铰接角 最大 43.27°` 互相印证。

依赖：`tf2_ros`、`geometry_msgs`（`package.xml` 已声明）。关掉广播用
`roslaunch trailer_kinematics main.launch tf_enabled:=false`。
