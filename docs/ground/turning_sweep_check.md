# 转弯扫掠校验

## 这一页解决什么问题

车在转弯时，车身扫过的不是一个圆，而是一个圆环：内侧后轮走小圆，外侧前角走大圆，两者之差就是**这个弯至少要多宽的通道**。轴距越长、前悬越长，这个环就越宽，窄路掉头、地下车库转弯、限宽门通过这些场景都会卡在这上面。

平时只能靠「打满方向盘试一下」，或者靠经验估。本页给出一个纯几何、纯标准库的实现：输入车辆几何参数和转弯半径，直接算出内轮差、外摆、所需通道宽度，并用四条断言判断这个弯能不能过。

> 本页原来的内容只有一条参考链接。下面的实现是在同一主题下补的：**不依赖 CARLA、不需要 GPU、不需要显示器**，一条命令在终端里出结果，方便在没有仿真环境的机器上做回归。

### 公式表

一律以后轴中心到转弯中心的距离 `R` 为基准（单位：米）。`L` 轴距，`b` 轮距，`fo` 前悬，`ro` 后悬：

| 量 | 公式 | 默认值下（R = 8.0） |
|---|---|---|
| 内后轮半径 | `R - b/2` | 7.230 |
| 外后轮半径 | `R + b/2` | 8.770 |
| 内前轮半径 | `hypot(R - b/2, L)` | 7.718 |
| 外前轮半径 | `hypot(R + b/2, L)` | 9.176 |
| 外前角半径 | `hypot(R + b/2, L + fo)` | 9.480 |
| 内后角半径 | `hypot(R - b/2, ro)` | 7.280 |
| 扫掠宽度（所需通道） | `max(所有半径) - min(所有半径)` | 2.250 |
| 内轮差 | `内前轮半径 - 内后轮半径` | 0.488 |
| 外摆 | `外前角半径 - 外前轮半径` | 0.304 |
| 最小可行半径 | `L / tan(最大前轮转角)` | 4.404 |

车身所有点到转弯中心的距离都在「内圈 ~ 外圈」之间，所以**扫掠宽度就是车身实际占用的环形通道宽度**，与画法、采样密度无关，是解析解而不是估算。

### 四条断言

| 断言 | 判据 | 不过时的含义 |
|---|---|---|
| 转弯可行性 | `R >= L / tan(最大转角)` | 方向盘打满也拐不过这个弯 |
| 通道宽度 | `扫掠宽度 <= channel_width` | 路/库位不够宽，会压线或剐蹭 |
| 内轮差 | `内轮差 <= max_inner_diff` | 轴距太大，内后轮会切进内角 |
| 内侧余量 | `内圈半径 >= inner_clearance` | 内侧贴着墙/护栏，没有安全余量 |

四条都过才是 `PASSED`。

### 反例

```bash
# 通道只有 2.0 m，比需要的 2.25 m 窄
roslaunch turning_sweep_check main.launch channel_width:=2.0

# 半径 4.0 m，比最小可行半径 4.404 m 还小
roslaunch turning_sweep_check main.launch turn_radius:=4.0
```

第一条只会让「通道宽度」这一条失败，第二条只会让「转弯可行性」失败 —— 每条断言互相独立，失败信息直接指出是哪个量不够、差多少。

### 常见问题

**为什么内圈取的是「内后轮」而不是「内后角」？**
默认参数下内后角 = `hypot(7.23, 0.85) = 7.280`，比内后轮 7.230 大，所以最小值仍是内后轮。后悬很长时内后角会更靠内，代码取的是所有半径的最小值，不写死。

**为什么 Melodic 上会看到 `UnicodeEncodeError`？**
Python 2.7 里 rosgraph 的日志格式化会对非 ASCII unicode 调 `str()`，直接炸。本模块所有日志都先编码成 byte str 再交给 `rospy.loginfo`（见 `turning_node.py` 的 `_log()`），所以中文日志在 Melodic 上安全。

**转弯半径填的是哪个半径？**
填后轴中心到转弯中心的距离。真车上常说的「最小转弯半径」通常按外侧车身算，可以用本模块的 `radii_at_limit()` 对比：默认参数下，后轴中心 4.404 m 对应外前角 9.480 m 量级的占用，两者不要混用。
