# 任务一：物理仿真与键盘运动控制

> **任务书原文**
>
> (1) 对人形机器人/肌肉骨骼人/车辆/水下机器人/无人机进行物理仿真，
> 通过键盘对机器人进行运动控制（5 分）。

---

## 1.1 实现目标

在 Gazebo 物理仿真环境中构建一台差速驱动无人车，通过键盘实时控制其
线速度与角速度，实现前进、后退、转向、加减速与紧急停止。

**验收要点**

| 要点 | 实现 |
|---|---|
| 物理仿真 | Gazebo 11 + ODE 物理引擎，步长 1 ms |
| 键盘控制 | 读取终端原始输入，20 Hz 下发速度指令 |
| 运动维度 | 线速度 x + 角速度 z（平面二自由度） |
| 安全机制 | 速度指令看门狗，超时自动停车 |

## 1.2 车体模型

### 1.2.1 几何结构

无人车采用经典**两轮差速驱动 + 前后万向轮支撑**布局：

```
                    俯视图
        ┌───────────────────────────────┐
        │                               │
        │          base_link            │
        │        （车体 0.44×0.38）      │
        │                               │
   ○────┤                               ├────○
  左驱动轮                              右驱动轮
        │                               │
        │                               │
        └───────────────────────────────┘
              ○                       ○
           前万向轮                 后万向轮
```

### 1.2.2 关键尺寸参数

| 参数 | 符号 | 值 | 说明 |
|---|---|---|---|
| 车长 | — | 0.44 m | 车体 x 方向尺寸 |
| 车宽 | — | 0.38 m | 车体 y 方向尺寸 |
| 车高 | — | 0.22 m | 车体 z 方向尺寸 |
| 车轮半径 | $r$ | 0.0975 m | 决定线速度与轮速换算 |
| 轮间距 | $L$ | 0.335 m | 左右轮中心距，决定转向能力 |
| 轮宽 | — | 0.05 m | — |
| 车体质量 | $m$ | 5.0 kg | 影响惯量与摩擦响应 |
| 离地间隙 | — | 0.0975 m | 等于车轮半径 |

### 1.2.3 离地高度的设计要点

车体中心的 z 坐标取：

$$
z_{\text{chassis}} = r + \frac{h_{\text{chassis}}}{2} = 0.0975 + 0.11 = 0.2075 \text{ m}
$$

**为什么必须这样做？**

若车体碰撞盒底面与地面接触（即 $z_{\text{chassis}} = h/2 = 0.11$），
Gazebo 会让车体与地面产生持续的法向力与切向摩擦。此时驱动轮虽在旋转，
但整车被地面摩擦"钉住"，表现为：

- 车轮关节角度持续累积（实测 30 秒转过 **168.9 rad**）
- 车辆实际位移几乎为零（实测 30 秒仅 **0.065 m**）
- `/cmd_vel` 正常发布，日志无任何报错 —— **极难排查**

抬高车体后，仅两个驱动轮与地面接触，摩擦驱动的运动学关系正常建立，
实测 30 秒可行驶 **6.31 m**。

### 1.2.4 垂向轮的处理

URDF 中万向轮为 `fixed` 关节的球体。若赋予其 `collision` 几何，
Gazebo 会将其视为与地面持续接触的刚体，产生额外滑动摩擦，
导致转向迟滞甚至卡死。

工程上有两类处理方式：

1. **真实的万向关节** —— 需 SDF 或自定义插件表达球铰，URDF 难以描述；
2. **保留为视觉件** —— 不参与碰撞计算，整车由驱动轮 + 车体离地间隙支撑。

本项目采用**方式 2**，这是 ROS 差速小车仿真中的常见做法。

## 1.3 运动学原理

### 1.3.1 差速驱动模型

差速底盘通过左右轮的**速度差**实现转向：

$$
v = \frac{v_r + v_l}{2}, \qquad \omega = \frac{v_r - v_l}{L}
$$

其中：

- $v$ —— 车体线速度 (m/s)
- $\omega$ —— 车体角速度 (rad/s)
- $v_l, v_r$ —— 左、右轮线速度 (m/s)
- $L$ —— 轮间距 (m)

**反解**（由 $v, \omega$ 求轮速）：

$$
v_l = v - \frac{\omega L}{2}, \qquad v_r = v + \frac{\omega L}{2}
$$

再由轮半径换算为角速度：

$$
\omega_l = \frac{v_l}{r}, \qquad \omega_r = \frac{v_r}{r}
$$

这一换算由 `gazebo_ros_diff_drive` 插件自动完成，控制器只需发布
`geometry_msgs/Twist` 到 `/cmd_vel`。

### 1.3.2 转向半径

给定 $(v, \omega)$，瞬时转向半径为：

$$
R = \frac{v}{\omega}
$$

- $\omega = 0$ → $R \to \infty$，直线行驶
- $v = 0, \omega \neq 0$ → $R = 0$，原地旋转
- $v \neq 0, \omega \neq 0$ → 圆弧运动

### 1.3.3 位姿积分

在二维平面下，车体位姿 $(x, y, \theta)$ 的演化方程为：

$$
\begin{aligned}
\dot{x} &= v \cos\theta \\
\dot{y} &= v \sin\theta \\
\dot{\theta} &= \omega
\end{aligned}
$$

Gazebo 的 `gazebo_ros_diff_drive` 插件通过积分离散化该方程，
发布 `/odom` 里程计话题。

## 1.4 键盘控制实现

### 1.4.1 增量式控制

键盘输入并非直接设定 $v$ 与 $\omega$，而是设定**速度增量**：

$$
v \leftarrow \text{clamp}(v + \Delta v,\; -v_{\max},\; +v_{\max})
$$

$$
\omega \leftarrow \text{clamp}(\omega + \Delta \omega,\; -\omega_{\max},\; +\omega_{\max})
$$

**设计理由**：这更接近真实遥控器的操作手感 —— 松开按键后车辆保持当前
速度继续行驶，需要主动按键才能改变状态。若采用"直接设定"模式，
一旦按键释放车辆立刻停止，无法进行长距离巡航。

### 1.4.2 按键映射

| 按键 | 作用 | 速度变化 |
|---|---|---|
| `w` | 前进 | $v \mathrel{+}= 0.1$ |
| `s` | 后退 | $v \mathrel{-}= 0.1$ |
| `a` | 左转 | $\omega \mathrel{+}= 0.2$ |
| `d` | 右转 | $\omega \mathrel{-}= 0.2$ |
| `q` | 前进 + 左转 | $v \mathrel{+}= 0.1,\; \omega \mathrel{+}= 0.2$ |
| `e` | 前进 + 右转 | $v \mathrel{+}= 0.1,\; \omega \mathrel{-}= 0.2$ |
| `z` | 后退 + 左转 | $v \mathrel{-}= 0.1,\; \omega \mathrel{+}= 0.2$ |
| `c` | 后退 + 右转 | $v \mathrel{-}= 0.1,\; \omega \mathrel{-}= 0.2$ |
| `空格` | 紧急停止 | $v = 0,\; \omega = 0$ |
| `+` / `-` | 调整速度上限 | $v_{\max} \pm 0.1$ |
| `x` | 退出 | — |

### 1.4.3 默认参数

| 参数 | 值 | 说明 |
|---|---|---|
| 线速度增量 $\Delta v$ | 0.1 m/s | 单次按键变化量 |
| 角速度增量 $\Delta \omega$ | 0.2 rad/s | 单次按键变化量 |
| 线速度上限 $v_{\max}$ | 0.8 m/s | 可运行时调节 |
| 角速度上限 $\omega_{\max}$ | 1.2 rad/s | — |

速度上限的约束依据：仿真中过高的速度会导致激光雷达单帧扫描周期内
（100 ms）车辆移动超过安全距离，来不及响应而撞墙。

### 1.4.4 终端原始模式

Linux 终端默认处于**规范模式**（canonical mode）：输入被缓冲到行尾
（回车）才交付给程序。这对实时遥控不可接受。

程序通过 `termios` + `tty` 切换到**原始模式**（raw mode）：

```python
self._settings = termios.tcgetattr(sys.stdin)   # 备份原设置
tty.setraw(sys.stdin.fileno())                  # 切换原始模式
```

退出时必须恢复，否则终端会残留异常状态：

```python
termios.tcsetattr(sys.stdin, termios.TCSADRAIN, self._settings)
```

### 1.4.5 非阻塞按键读取

原始模式下 `sys.stdin.read(1)` 会阻塞等待输入，导致主控制循环卡死。
程序使用 `select` 实现非阻塞轮询：

```python
dr, _, _ = select.select([sys.stdin], [], [], 0)   # 超时 0 秒
if dr:
    return sys.stdin.read(1)
return None
```

这样主循环可以保持 20 Hz 稳定运行，同时随时响应按键。

### 1.4.6 无终端时的降级行为

通过 `roslaunch` 后台启动时，进程没有交互式终端（`sys.stdin.isatty()`
返回 `False`）。此时程序**自动切换为自动巡航模式**：车辆以固定速度
持续前进，保证仿真仍可运行并产出轨迹数据。

这一设计使本项目既能交互式操作，也能**无人值守地批量采集实验数据**
（本项目第五节的实验数据即由该模式采集）。

## 1.5 源码解析

**文件**：`scripts/teleop_keyboard.py`

### 1.5.1 类结构

```
TeleopKeyboardNode
├── __init__(watchdog)          初始化速度状态与终端检测
├── start()                     启用终端原始模式
├── stop()                      恢复终端设置
├── update()                    ★ 主循环：读键 → 更新速度 → 发布
├── _read_key()                 非阻塞读取一个字符
├── _handle_key(key)            按键映射到速度变化
├── _publish()                  构造并发布 Twist
└── _print_status()             单行刷新显示当前速度
```

### 1.5.2 核心流程

```
     ┌──────────────────┐
     │  update() 调用    │  ← 由 main.py 以 20 Hz 驱动
     └────────┬─────────┘
              ▼
     ┌──────────────────┐
     │  _read_key()     │  非阻塞 select，超时 0 s
     └────────┬─────────┘
              │
        ┌─────┴─────┐
        │ 有按键？   │
        └─────┬─────┘
         否   │   是
      ┌───────┘   └────────┐
      │                    ▼
      │          ┌──────────────────┐
      │          │ _handle_key()    │  速度增量 + 限幅
      │          └────────┬─────────┘
      │                   │
      └─────────┬─────────┘
                ▼
     ┌──────────────────┐
     │  _publish()      │  构造 Twist → watchdog.feed()
     └──────────────────┘
```

### 1.5.3 关键代码

**速度限幅**（防止累积超出上限）：

```python
self._linear = max(-self._linear_max,
                   min(self._linear, self._linear_max))
self._angular = max(-self._angular_max,
                    min(self._angular, self._angular_max))
```

**速度发布**（经看门狗统一出口）：

```python
def _publish(self):
    cmd = Twist()
    cmd.linear.x = self._linear
    cmd.angular.z = self._angular
    self._watchdog.feed(cmd)      # feed() 内部完成 publish
```

> **注意**：`feed()` 必须真正调用 `publish()`。早期实现中 `feed()` 只
> 缓存指令、由 `check()` 在超时后才发布，导致正常指令永远发不出去 ——
> 表现为 `/cmd_vel` 完全无消息。该缺陷已修复，详见
> [工程问题排查记录](troubleshooting.md)。
