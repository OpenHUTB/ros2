# 纵向速度控制：按曲率自动限速与速度跟踪

## 1. 为什么做这个模块

仓库内地面载具已有多个**横向**控制实现：

| 模块 | 作用 |
|---|---|
| [阿克曼控制](./ackermann_control.md) | 把目标转向角映射到底层控制 |
| [路径点发布器](./waypoint.md) | 生成/转发路径点 |
| [车道保持控制](./carla_lane_keeping/lane_keeping_control.md) | 由车道线偏差闭环出转向量 |

但**没有任何纵向速度控制**。缺少纵向控制的直接后果是：车辆只能定速行驶。

- **过弯不减速**：横向加速度 `a_lat = v²·κ` 随速度平方增长。以 12 m/s 通过
  半径 40 m 的弯道时，`a_lat = 3.6 m/s²`；而干燥沥青路面的轮胎附着能力大约
  在 0.3~0.4 g（约 3~4 m/s²）量级，再快就会侧滑失稳。
- **直线不能加速**：为保证能过最急的弯，只能把全程速度压低，通行效率损失大。

本模块补上这一环：**由路径曲率反解安全车速，并把这个速度闭环跟踪住**。

它与车道保持模块的分工：

```
前视相机 → 车道线检测 → 曲率 ──┐
                                ├─→ 本模块 → 加速度指令 → 车辆
目标速度 ──────────────────────┘
```

## 2. 处理流程

```
                    ┌──────────────────────────────────────┐
   路径曲率 κ(s) ──→ │ 1. 限速计算                          │
                    │    v_max = sqrt(a_lat,max / |κ|)·η   │
                    │    取前瞻窗口内**最大**曲率           │
                    └──────────────┬───────────────────────┘
                                   │ v_limit
                                   ▼
   目标速度 ──────────────────→ min(巡航, v_curvature)
                                   │
                                   ▼
                    ┌──────────────────────────────────────┐
                    │ 2. 速度跟踪（PID + 前馈）             │
                    └──────────────┬───────────────────────┘
                                   │ a_pid
                                   ▼
                    ┌──────────────────────────────────────┐
                    │ 3. 预瞄制动（取更保守者）             │
                    └──────────────┬───────────────────────┘
                                   │ a_cmd
                                   ▼
                    ┌──────────────────────────────────────┐
                    │ 4. 超速兜底                           │
                    └──────────────┬───────────────────────┘
                                   │
                                   ▼
                    ┌──────────────────────────────────────┐
                    │ 5. jerk 限制（最后一步）              │
                    └──────────────┬───────────────────────┘
                                   ▼
                            加速度指令 a
```

### 2.1 限速公式与安全系数

匀速圆周运动的横向加速度为 `a_lat = v²·κ`，反解得

```
v_max = sqrt(a_lat,max / |κ|) · η
```

`η` 是安全系数（默认 0.995）。**为什么需要它**：理论上 `η = 1` 时横向加速度
恰好等于限值，但在离散控制（步长 0.05 s）中速度会在限值附近有微小波动。
实测 `η = 1` 时最大横向加速度为 3.01 m/s²，比设定的 3.0 高 0.3%；留 0.5%
的速度余量后严格不超限，代价是过弯速度低 0.5%（39.4 → 39.2 km/h）。

### 2.2 为什么前瞻要取窗口内最大曲率，而不是单点

**这是本模块踩过的最大的坑。**

最初的实现按"当前速度 × 前瞻时间"算出前瞻距离，然后在该距离处**插值取单点
曲率**。结果最大横向加速度达到 **3.59 m/s²**，超出 3.0 的限值 20%。

原因：单点取值会漏掉前瞻窗口内的曲率峰值。如果该点恰好落在缓和段（或恰好
避开峰值），算出的限速偏大；车辆按这个偏大的限速继续加速，等真正开到弯心时
真实曲率已经更高，横向加速度随之超标。

改为**取前瞻窗口内绝对值最大的曲率**后，问题解决。工程含义很清楚：
**限速要看最坏情况，不是眼前那一点。**

实现上是向量化的滑动窗口最小值（对限速数组取窗口最小），不做逐点循环。

### 2.3 预瞄制动：从"事后纠正"变成"提前规划"

仅靠 PID 跟踪限速时，由于动力总成有时间常数（仿真中取 0.8 s），车辆在减速段
一定会超出限速——实测超速 0.83 m/s，进而使横向加速度超标。

预瞄制动解决这个问题：找出**前方第一个限速低于当前车速的点**，用匀减速公式

```
v² = v₀² + 2·a·d   →   a = (v_future² - v_now²) / (2·d)
```

算出所需减速度，与 PID 输出取更保守的那个（即更小、更偏减速）。

效果：**最大超速从 0.83 m/s 降到 0.000 m/s**，超速兜底层完全不再介入
（介入率 0.0%）。这说明控制律是"提前规划"的，而不是"越界后补救"。

### 2.4 为什么 jerk 限制必须放在最后一步

加速度指令如果允许阶跃，乘客会感到明显顿挫；机械上也会冲击传动系统。

**踩过的坑**：加入超速兜底层时，兜底输出直接覆盖了 PID 的输出，**绕过了
jerk 限制**。结果最大 jerk 达到 **40.45 m/s³**（限值 4），是限值的 10 倍，
表现为突然急刹。

正确做法是把 jerk 限制放在**控制链路的绝对最后一步**，任何安全层/限速层的
输出都必须经过它。修正后最大 jerk 恰好为 4.00 m/s³，严格不超限。

同时控制器内部提供了 `sync_accel()`：当外层在 `update()` 之后又施加了修正时，
必须把真实施加的加速度同步回控制器，否则下一次 jerk 限制会基于一个并未真正
执行的旧值计算，限制失效。

### 2.5 单位约定

本模块**统一使用国际单位制**：m/s、m/s²、m/s³、1/m、m、s。
这与 ROS 的 `geometry_msgs/Twist`（m/s）和 CARLA 控制接口一致。

仓库里部分模块用 km/h 描述车速，本模块在**参数与话题层面**一律用 m/s，
只在文档的展示表格里换算成 km/h，避免单位混用导致的隐蔽错误。

### 2.6 限速剖面的可达性约束（踩坑记录）

仅靠"几何限速 + 前瞻窗口"会算出**物理上无法实现**的限速剖面，需要额外两步扫描。

**问题表现**：两个弯之间只有 55 m 直道时，前瞻窗口（60 m）在直道中段恰好避开
前后两个弯，几何限速于是跳回巡航速度 12.0；相邻点又因窗口覆盖到曲率峰值而掉回
10.90，形成锯齿。

**修正**：对几何限速做**双向可达性扫描**——

* 反向扫描（限制加速）：`v_i ≤ sqrt(v_{i+1}² + 2·a_max·Δs)`
* 正向扫描（限制减速）：`v_{i+1} ≤ sqrt(v_i² + 2·a_decel·Δs)`

物理含义是"加速上去再刹回来必须来得及"。实测该扫描把直道中段的限速从 12.0
压到 10.90，消除了不可实现的尖峰。

**这里踩过一个很难发现的坑**：扫描的结果写进了局部变量，但函数**返回的仍是
未经扫描的几何限速**。这类"算完没用上"的错误不产生任何报错，90 个测试也全部
通过——只有盯着输出曲线才能发现。为此专门补了 6 个测试
（`TestAchievableProfile`），其中 `test_achievable_actually_differs_somewhere`
直接验证"扫描确实作用到了返回值"。

### 2.7 出弯斜坡上的限速回升（正常现象，勿误判为缺陷）

剖面在**弯道出口的缓和段**会出现一个约 0.5 m/s 的小回升，例如：

```text
      s       曲率     限速
    168   0.02500   10.900   ← 弯道中段
    169   0.02083   11.437   ← 出弯斜坡：曲率递减，允许边转向边加速
    171   0.01250   11.172
    172   0.00833   10.900   ← 下一弯进入前瞻窗口，限速回落
```

这是**物理正确**的：该点 `a_lat = 11.437² × 0.02083 = 2.72 m/s²`，仍在
3.0 的限值内。曲率递减时车辆可以加速，只要横向加速度不超限。

**排查中的教训**：这个 0.5 m/s 的回升曾被误认为是算法缺陷，原因是演示脚本里
用于"裁掉起步段"的判据写成了 `v > v_limit - 2.0`，而该条件在有控制时**恒成立**
（限速从不被突破，故 `v - v_limit ≤ 0`），导致掩码全为 False、裁剪失效、起步
段未被裁掉。画面上于是同时出现起步斜线与出弯回升，被错误地解读为"限速尖峰"。
正确判据是 `|v - v_limit| < 0.5`。

## 6. 参数说明

参数文件：`config/speed_params.yaml`

### 6.1 目标速度

| 参数 | 默认 | 说明 |
|---|---|---|
| `target_speed` | 12.0 | 无曲率限制时的巡航速度（m/s），≈ 43.2 km/h |

### 6.2 PID 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `kp` | 1.0 | 比例增益 |
| `ki` | 0.15 | 积分增益。取值偏小以抑制超调 |
| `kd` | 0.35 | 微分增益，抑制超调的主要手段 |
| `kff` | 1.0 | 前馈增益 |
| `integral_limit` | 2.0 | 积分项上限，防止饱和 |

### 6.3 载具能力约束（**换车后必须重新标定**）

| 参数 | 默认 | 说明 |
|---|---|---|
| `max_accel` | 3.0 | 满油门加速度（m/s²） |
| `max_decel` | 6.0 | 满刹车减速度（m/s²） |
| `max_jerk` | 4.0 | 加速度变化率上限（m/s³），0 表示不限制 |
| `max_lateral_accel` | 3.0 | 容许横向加速度（m/s²），**决定过弯速度上限** |
| `min_speed` | 1.0 | 最低速度，避免曲率噪声把车速压到近 0 |

### 6.4 标定方法

**（1）标定 `max_accel` / `max_decel`**

找一段直道，从静止全油门加速，记录速度曲线；加速度的稳态值即 `max_accel`。
刹车同理。CARLA 默认车辆（`vehicle.tesla.model3`）约 3.0 / 6.0 m/s²。

**（2）标定 `max_lateral_accel`**

这是唯一**影响过弯速度**的参数，也是最需要按实际需求选择的：

- 追求安全（湿滑、乘客舒适）：取 2.0~2.5 m/s²（约 0.2~0.25 g）
- 常规干燥路面：取 3.0~4.0 m/s²（约 0.3~0.4 g）
- 上限受轮胎附着能力约束，超过就会侧滑

**（3）标定 `max_jerk`**

从乘客舒适度出发取值。经验范围：1~2 m/s³ 很平顺，4 m/s³ 可感知但不难受，
10 m/s³ 以上会有明显顿挫。

**（4）验证**

```shell
python3 tests/demo_speed_control.py --cruise <你的巡航速度> --radius <弯道半径>
```

观察输出的"最大横向加速度"是否 ≤ `max_lateral_accel`。

## 7. 实测结果

### 7.1 仿真场景

路径：直道 100 m → 左弯（半径 40 m）120 m → 直道 100 m → 右弯 120 m → 直道。
巡航速度 12.0 m/s，控制频率 20 Hz，仿真步长 0.05 s。

### 7.2 对比结果

| 指标 | 无纵向控制 | 有本模块 | 说明 |
|---|---|---|---|
| 最大横向加速度 (m/s²) | **3.600** | **2.977** | 前者为限值的 1.20 倍 |
| 最大超速 (m/s) | — | **0.000** | 兜底层介入率 0.0% |
| 最大 \|jerk\| (m/s³) | — | **4.00** | 正好在限值内 |
| 稳态速度误差 (m/s) | — | **0.012** | ≈ 0.04 km/h |
| 平均速度 (m/s) | 12.00 | 10.47 | 弯道减速的代价 |
| 总时间 (s) | 33.3 | 38.25 | 慢 4.9 s 换取不失稳 |

**关键结论**：没有纵向控制时车辆以 12 m/s 定速过弯，横向加速度 3.60 m/s²
超过设定的 3.0 m/s² 上限 20%，对应约 0.37 g——已接近干燥路面的附着极限。
本模块在弯前把车速降到 10.90 m/s（39.2 km/h），实测最大横向加速度 2.98 m/s²，
始终在限值内。

### 7.3 约束满足情况

| 约束 | 限值 | 实测 | 是否满足 |
|---|---|---|---|
| 横向加速度 | 3.0 m/s² | 2.977 m/s² | ✓ |
| 加速度 | 3.0 m/s² | 3.00 m/s² | ✓ |
| jerk | 4.0 m/s³ | 4.00 m/s³ | ✓ |
| 超速（含容差） | 0.2 m/s | 0.000 m/s | ✓ |

## 8. 常见问题

**Q: 车辆在弯道里还是超速**

按顺序检查：

1. `speed/curvature` 是否真的在更新？`rostopic hz /speed/curvature`
2. 曲率超时参数是否太大？`curvature_timeout` 默认 0.5 s，超过就按直道处理
3. `max_lateral_accel` 是否设得过大，导致限速本身就偏高？

**Q: 加减速太突兀**

调小 `max_jerk`（如 2.0）。它直接限制加速度变化率。

**Q: 车辆在弯道里速度偏低、影响效率**

`max_lateral_accel` 设小了。干燥路面可以取到 3.5~4.0 m/s²。

**Q: 里程计没接上时行为如何**

节点会退化为"用上一拍指令积分"估计速度，并每 10 秒打印一次警告。
这种估计不准确（没有阻力与坡道项），建议接上里程计。

**Q: 直道上莫名其妙保持弯道限速**

不应该发生——曲率超时后会按直道（κ=0）处理。若出现，检查
`curvature_timeout` 是否被设得过大。

## 9. 后续改进方向

1. **道路坡度补偿**：当前模型没有坡度项。上坡时需要额外驱动力，
   可用 IMU 的俯仰角估计坡度，把 `m·g·sin(θ)` 作为前馈加入。
2. **前车跟随（ACC）**：订阅前车距离与相对速度，把安全车距对应的速度
   也纳入限速取最小值。这与本模块的"多约束取最小"结构天然兼容。
3. **经济性优化**：当前只考虑安全与舒适，没有考虑能耗。可加入
   "避免不必要的加速-减速循环"的代价项。
4. **执行器延迟辨识**：仿真中 `τ = 0.8 s` 是估计值。实车上可用阶跃响应
   辨识真实延迟，代入前馈补偿。
