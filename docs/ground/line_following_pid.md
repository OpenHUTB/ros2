# 循线小车 PID 横向控制（line_following_pid）

演示经典 PID 循线控制：小车沿正弦赛道行驶，实时计算相对中心线的横向误差，用 PID 输出前轮转角。

## 环境

- Windows 11，Python 3.13.16，pygame 2.6.1

## 运行

见包内 README。`python main.py` 会打开 pygame 窗口，需要在有显示的环境下执行；`launch/main.launch.py` 只是把同名可执行文件包装成 ROS 2 launch 入口，同样是窗口程序，不能替代真实 ROS 节点。

## 分层

- track.py：正弦赛道采样、最近点查询、横向误差计算。
- pid.py：PID 控制器，含比例、积分、微分项与输出限幅。
- car.py：自行车运动学推进车身，按 PID 输出转向。
- main.py：pygame 可视化，显示赛道、轨迹、小车朝向与实时误差。

## 实测结果

本地复跑 529 步跑完整条赛道：起步横向误差 18.12 px，最大绝对横向误差 23.93 px，终点误差 -6.44 px。全程 8 次穿越中心线，后半段误差峰峰值 16.35 px，末段仍有小幅漂移。

## 与 line_follower_car 的区别

仓库里另有 [`line_follower_car`](./line_follower_car.md)，同样做二维巡线小车，容易与本文混淆。两者的选题相邻，但被控量、感知方式和想观察的现象不同：

- **控制回路不同**。本模块把车辆相对中心线的**带符号横向误差**送进 **PID**（含积分项和输出限幅），输出量是**前轮转角**，因此可以看到积分项把稳态偏差慢慢压掉的过程；`line_follower_car` 取预瞄点，用的是**朝向误差 + PD**，输出量是**转向角速度**，没有积分项，本质是 pure pursuit 思想的跟踪。
- **感知方式不同**。本模块靠几何投影：在正弦中心线上找最近采样点，用相邻点估切向、取右手法向做点乘，得到连续的横向误差；`line_follower_car` 靠车头五个**虚拟光传感器**按到线的距离判定是否压线，反馈是离散的。
- **可视化方式不同**。本模块用 **pygame** 开窗口实时画赛道、轨迹、车头朝向和误差 HUD，偏重把控制过程演给人看；`line_follower_car` 用 **NumPy + Matplotlib**，偏重 `--headless` 出 `metrics.json` 做批量评测。
- **车辆模型不同**。本模块是**自行车模型**（轴距 18 px，前轮转角积分成航向）；`line_follower_car` 是**独轮模型**（直接积分角速度），赛道是带内凹弯的闭合折线，本模块是固定正弦曲线。

简单说：`line_follower_car` 回答"传感器压线 + 预瞄点 PD 能不能跑完一圈"，本模块回答"横向误差经 PID 后前轮转角如何把车拉回中心线、超调和稳态偏差长什么样"。两个条目各自保留，不互相替代。

## 限制

- 纯 2D 几何演示，车辆用简化自行车模型，不接真实定位与控制器话题。
- 赛道固定为正弦曲线，未做鼠标点选交互。
- 积分项没有单独限幅：`PID` 只对总输出做限幅（`config.MAX_TOTAL = 20` 弧度），前轮转角在 `car.py` 里再按 `MAX_STEER = 0.35` 弧度夹紧，因此 20 弧度的输出限幅实际不会触发，真正起作用的是 0.35 弧度的转角夹紧。
