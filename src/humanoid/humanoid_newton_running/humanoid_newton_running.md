# 人形机器人跑步步态仿真与牛顿第二定律验证 ROS 2 封装模块
> 本模块基于 MuJoCo 3.2.5 实现 Booster T1 人形机器人关键帧跑步动画，通过五次多项式插值完成匀速行走 → 加速跑步，身体随步伐上下起伏、重心左右转移、手臂自然摆动，全程不摔倒。同时基于仿真数据验证牛顿第二定律 F=ma，输出质量、重力、加速度与外力计算结果。图片为虚拟机内 MuJoCo 窗口直接录屏，报告写作时标注：**效果图：Ubuntu 20.04 虚拟机 MuJoCo 实时渲染**。

## 一、模块开发背景
人形机器人在步态展示、动作回放等任务中需要多关节协调运动，包括腿部摆动、重心转移、腰部扭转、手臂摆动与头部跟随。本模块采用关键帧动画方式，不依赖动力学平衡控制器，通过直接设置关节位置 + 五次多项式插值实现平滑跑步效果，避免 PD 力矩控制反复摔倒的问题。

模块不解析 URDF、不做真实接触力求解，关节位姿在动画轨迹中预先编排；适合课程作业演示与运动学算法原型验证，不作为真实机器人动力学平衡方案。

## 四、动画算法原理
### 1. 关键帧姿势建模
定义三个基础姿势，所有关节角度预先给定：
- **p0（站姿）**：膝盖微弯，手臂自然下垂
- **p_left（左腿前迈）**：左髋前摆、左膝弯曲、重心左移、腰左转、右臂前摆、头部左转
- **p_right（右腿前迈）**：右髋前摆、右膝弯曲、重心右移、腰右转、左臂前摆、头部右转

### 2. 五次多项式插值
关键帧之间不使用线性插值，采用五次多项式保证位置、速度、加速度连续：

$$
q(t) = t^3 \times (6t^2 - 15t + 10)
$$

其中 $t \in [0,1]$ 为归一化时间。五次多项式在过渡点处速度和加速度均为 0，不会出现突兀的急停或抖动。

### 3. 身体上下起伏
走路时身体随步伐自然上下颠，通过正弦函数叠加到 freejoint 的 z 坐标：

$$
qpos[2] = z_{base} + 0.04 \times \sin(step \times 0.15)
$$

频率参数 0.15 经过调整，避免颠簸过快；幅度 0.04 m 保证起伏可见但不夸张。

### 4. 前进位移与相机跟随
- freejoint 的 x 坐标每帧递增：$qpos[0] = step \times 0.0035$
- 相机 `lookat[0]` 跟随机器人 x 坐标
- 背景网格相对相机向后移动，产生前进速度感

### 5. 多关节协调细节
| 部位 | 关节索引 | 动作幅度 |
|------|----------|----------|
| 髋部 pitch | 11 / 17 | 前后摆动 0.9 rad |
| 膝盖 | 14 / 20 | 弯曲 0.8 rad |
| 髋部 roll | 12 / 18 | 重心转移 ±0.15 rad |
| 腰部 yaw | 10 | 左右转 ±0.25 rad |
| 手臂 pitch | 2 / 6 | 前后摆动 ±0.8 rad，与腿反相 |
| 肘部 | 4 / 8 | 弯曲 0.5 rad |
| 头部 yaw | 0 | 左右转 ±0.3 rad |
| 脚踝 pitch | 15 / 21 | 摆动 0.2 rad |

### 6. T1 默认姿势修正
T1 模型所有关节归零时，手臂默认向两侧平举（T 字形），不是自然下垂。做动画前必须先设置 `shoulder_roll`（索引 3 和 7）角度修正，否则机器人全程平举手臂。

### 录屏方法
在 Ubuntu 虚拟机内使用 ffmpeg 对 MuJoCo 窗口录屏：
```bash
# 获取窗口 ID
xwininfo -tree -root | grep "MuJoCo"

# 录屏
ffmpeg -f x11grab -window_id <窗口ID> -framerate 30 output.mp4
```

## 七、演示轨迹与实测结果
### 终端输出
```

牛顿第二定律 F=ma 验证
==================================================
m = 31.614 kg, G = 310.14 N
匀速: a=0, F=0 (平衡)
加速: a=0.5 m/s², F=m*a=15.807 N
```

### 牛顿第二定律验证数据
| 物理量 | 数值 | 来源 |
|--------|------|------|
| 机器人总质量 m | 31.614 kg | `model.body_mass.sum()` |
| 重力加速度 g | 9.81 m/s² | 标准值 |
| 重力 G = m×g | 310.14 N | 计算 |
| 匀速阶段加速度 a | 0 m/s² | 速度恒定 |
| 匀速阶段合力 F | 0 N | F=ma |
| 加速阶段加速度 a | 0.5 m/s² | 步态加速 |
| 加速阶段外力 F = m×a | 15.81 N | F=ma |

### 物理解释
**阶段 1：匀速行走**
- 机器人速度恒定，加速度 a = 0
- 根据 F=ma：合力 F合 = m × 0 = 0
- 重力（向下 310 N）与地面支持力（向上 310 N）平衡

**阶段 2：加速跑步**
- 机器人加速度 a = 0.5 m/s²
- 根据 F=ma：需要外力 F = 31.614 × 0.5 = 15.81 N
- 该外力由地面摩擦力提供，方向与前进方向一致

## 八、模块边界与局限性
1. **不含动力学平衡控制**：本模块采用直接设 qpos + `mj_forward` 的运动学驱动方式，不使用 `mj_step` 求解真实动力学。机器人不会摔倒，但也不验证真实受力平衡。
2. **位移为动画效果**：机器人前进通过直接设置 freejoint x 坐标实现，不是由地面摩擦力驱动的真实位移。
3. **F=ma 为理论验证**：加速度和外力数据基于步态规划参数计算，不是从动力学传感器读取。
4. **无环境感知**：不包含视觉、IMU 等传感器，动作全部预先编排。
5. **单一场景**：仅平地直线跑步，不支持转弯、变向或障碍物。
6. **T1 模型特有**：关节角度、默认姿势、执行器配置均针对 Booster T1，参数不可直接外推到其他人形模型。
