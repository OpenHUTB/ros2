# 开发过程记录（uav_traffic_nav）

按时间顺序记录这次迭代做了什么、看到什么、为什么改。数字都来自本机 CPU 实跑。

## 1. 搭骨架

* 照 `uav_ppo_nav` 的接口写共享模块：34 维观测（多 12 维车辆相对状态）、4 维世界系动作。
* 环境：质点 + 速度环一阶滞后 + 车道车流；奖励 = 进度 + TTC 惩罚 + 碰撞/到达。
* 基线：`greedy`（无视车）与 `vo`（速度障碍法），用于对照。
* 28 项纯 Python 单测（无需 ROS/仿真器）。

## 2. 第一版训练（300k 步，3 车道、3 车/车道）

* 结果：成功率 34%，碰撞 66% —— **和 greedy（36%）没有区别**，等于没学会。
* 诊断：14% 的重置直接在车体内出生（回合一开始就判定碰撞），训练信号被污染；
  3 车道 + 3 车/车道的密度对 3 m/s 的无人机过于苛刻。

## 3. 第二版（安全出生点 + 近距惩罚，300k）

* 加了"出生点与车至少 2.5 m"和"距车 2 m 内扣分"。
* 结果更差：reward -34，episode 长度 19 步。
* 原因：近距惩罚太强（每步最多 -4），策略学会"远离车道"，但任务要求跨路，
  于是既不敢过又拿不到目标，形成"负奖励陷阱"。

## 4. 第三版（2 车道、半径调小、去掉近距惩罚，400k）

* 车半径 1.0、无人机 0.3（碰撞圆 1.3 m），碰撞罚 -30，TTC 罚保留。
* 结果（难度 0.8，100 回合）：

| 策略 | 成功率 |
| --- | --- |
| policy_traffic | 61% |
| policy_lidar_only（消融，权重未保留） | 57% |
| greedy | 55% |
| vo | 46% |

* 强制跨路分布下零样本：48% / 33% / 20%。
* 结论：方向对（有相对速度特征 > 纯激光 > 贪心 > VO），但默认分布对贪心太宽容，
  差距只有 6 个百分点，还不足以作为"学会避障"的证据。

## 5. 第四版：直接在"强制跨路"分布上训练（失败）

* 把训练分布也改成"起点/终点固定在车道两侧"（`--force-crossing`），车流加密到
  2 辆/车道、3–6 m/s，碰撞罚 -30 → -60，TTC 时间窗 2.5 s；3 个种子 × 2 种观测。
* 结果：**全部 0% 成功率、100% 碰撞**，比贪心（26%）还差。平均最小间距 1.16 m
  （说明策略学会了"保持距离"，但始终不敢穿过，最后被车撞）。
* 诊断：强制跨路分布下**几乎没有成功样本**——每一回合都在穿路时结束，
  价值函数学不到"到达目标"的正向信号，策略退化成"远离车道 + 乱飞"。
  同一个环境在**混合分布**（随机起终点，约一半回合需要跨路）训练时反而有 48% 零样本成功率。
* 结论：**训练分布要有成功样本**；评测可以用更严格的强制跨路分布。

## 6. 第五版（当前）：混合分布 + 更密车流，多种子

* 训练：随机起终点（自然包含跨路），2 辆/车道、3–6 m/s、难度 1.0，400k 步，
  3 个种子 × {34 维, 22 维}，并行训练。
* 评测：强制跨路 + 难度 1.0（比训练更严格），100 回合/模型，报告均值±标准差。
* 结果：**34 维版本 3 个种子全部退化到 0%**；22 维版本 34.7% ± 3.2%。
  相比之下，第三版（塑形较温和：碰撞 -30、TTC 1.0×2.0 s）训练出的 34 维模型在同一
  评测协议下有 36%。也就是说：**同样的数据，更强的安全惩罚反而破坏了训练**。
* 同协议下的基线：贪心 26%、速度障碍法 13%、最佳 PPO 36%（强制跨路）；
  混合分布下分别是 47% / 41% / 55%。
* 结论：提升真实但温和（+10 个百分点），且对奖励塑形/训练预算高度敏感，
  **当前版本不足以作为 PR 提交**；下一步用示范引导（DAgger 预热）比继续调 PPO 更划算。

## 7. 第六版：示范引导（当前主策略）

* 先写规则专家：车道前 3 m 等窗口，确认 1.2 s 内没有车经过再穿（强制跨路 75%）。
* 采 9k 条专家示范做行为克隆（BC 单独只有 13%——分布漂移就崩）。
* 3 轮 DAgger（学生自己飞、在到达状态贴专家标签）：学生成功率 20% → 42% → 50% → 52%。
* 再从 DAgger 权重做 PPO 微调：同分布 64% → 68%，但强制跨路 52% → 41%（过拟合训练分布），
  所以默认导出 DAgger 策略。

最终对比（难度 1.0，100 回合/条件，seed 11）：

| 策略 | 混合 | 强制跨路 |
| --- | --- | --- |
| 规则专家（特权信息） | 72% | 75% |
| **BC + DAgger（3 种子）** | **61.0% ± 3.0%** | **48.0% ± 3.6%** |
| BC + DAgger + PPO | 68% | 41% |
| PPO 从零 | 61% | 44% |
| greedy | 57% | 39% |
| 速度障碍法 | 53% | 19% |

三个 DAgger 种子的学生成功率曲线（DAgger 各轮）：20→42→50、32→30→58、10→42→60，
最终强制跨路 48.0% ± 3.6%，说明结论不是单次运气。

## 8. 文件命名说明

迭代过程中的 `policy_traffic.npz` 已重命名为 `ppo_scratch.npz`（它就是"PPO 从零"基线，
不是最终策略）；`bc_policy.npz` 与 `bc_policy_s42.npz` 是同配置重复，已删除后者以外的副本，
部署默认加载 `models/bc_policy_s42.npz`。

## 9. 踩过的坑

* **出生点撞车**：不处理会让 ~14% 的回合在第一步就结束，训练曲线完全失真。
* **奖励塑形过强**：近距惩罚会把策略逼成"不敢靠近车道"，反而学不会等待时机。
* **评测分布与训练分布不一致**：默认分布下贪心就有 55%，测不出策略价值；
  必须用"强制跨路"这类贪心必然吃亏的分布才能拉开差距。
* 训练日志与旧任务并发写同一个 `models/` 目录会互相覆盖，需要按名字分开。
