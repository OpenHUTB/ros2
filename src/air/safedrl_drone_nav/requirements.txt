# SafeDRL-DroneNav-ROS - Python dependencies

# Target: Ubuntu 20.04 + ROS Noetic (Python 3.8) for the ROS nodes.
#         The offline training pipeline runs on Python 3.10 (developed and
#         verified on Windows 11 with the conda-forge PyBullet build).
#
#     pip install -r requirements.txt
#
# NOTE ON PYBULLET
# ----------------
# PyBullet publishes NO Windows wheels on PyPI; `pip install pybullet` tries to
# build from source and fails without MSVC build tools.  This is an upstream
# packaging limitation and does not affect the target platform - on Ubuntu the
# pip install works normally:
#
#     pip install pybullet                     # Ubuntu (recommended)
#
# Only if you are reproducing the artefacts on Windows, take the prebuilt
# conda-forge package instead of building from source:
#
#     conda install -c conda-forge pybullet "numpy<2"
#
# (If conda-forge's numpy is installed, re-install the pip wheel afterwards -
# `pip install --force-reinstall --no-deps numpy==1.26.4` - because the
# conda-forge build linked against an MKL that makes `numpy.linalg.inv` abort
# the process with a DLL delay-load error.)

# --- offline verification environment ----------------------------------

# tests/test_environment.py.  It is not the course simulator; the course

# (requirements-sim.txt, models/quadrotor_scene.xml).
