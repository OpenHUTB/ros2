# 雨雾天气下的自适应感知降级策略

「恶劣雨雾天气下多传感器感知性能对比」系列的第五部分（收官）。前三部分量化了相机退化、
图像增强的恢复上限、雷达与相机的横向对比，第四部分验证了雷达投影到图像的融合可行性。
本部分把结论落地成一个可运行的策略：**由图像判别当前天气等级，再自动切换感知模式**。

## 策略

| 判别出的天气 | 依据（边缘密度 / 晴天基准） | 采用模式 |
| --- | --- | --- |
| ClearNoon | ≥ 0.85 | 相机主导 |
| SoftRainNoon | 0.50 ~ 0.85 | 融合（相机 ∪ 雷达） |
| HardRainNoon | 0.19 ~ 0.50 | 融合（相机 ∪ 雷达） |
| HeavyFog | < 0.19 | 雷达主导 |

三个阈值取在本模块实测四档比值（1.00 / 0.77 / 0.24 / 0.16）相邻两档的中点，
`ref` 由第一档（晴天）现场测得，因此判据不依赖人工设定的绝对亮度。

## 场景与传感器

- 同一辆车、同一参考位姿，四档天气各测一次。
- ego 正前方按 10 / 16 / 22 / 28 / 34 / 40 m 逐辆放置目标车：**同一时刻只有一辆车**，
  测完销毁再测下一档距离。一次摆 6 辆时，后车会被前车挡住（投影框里装的是前车车身），
  左右错开又会摆到路缘和绿化带上，逐车测量可同时避开这两个问题。
- `sensor.camera.rgb`：800×600、FOV 90°，安装于 x=1.5、z=2.4。
- `sensor.lidar.ray_cast`：32 线、50 m、20 Hz、60 万点/秒，安装于 x=0.0、z=2.6；
  按天气档位写入 `atmosphere_attenuation_rate`（0.004 / 0.01 / 0.03 / 0.06）。
- 雷达按渲染帧发布（单帧仅约 45° 扇形），因此按 0.2 s 时间窗累积成整圈；测量期间车辆静止。

## 判据

| 判据 | 定义 |
| --- | --- |
| 相机可检出 | 目标投影框内与框外环形背景的平均亮度对比度 ≥ 0.10 |
| 雷达可检出 | 目标 3D 包围盒（外扩 0.25 m）内回波点数 ≥ 5 |
| 融合 | 相机与雷达取并集 |
| 自适应 | 按判别出的天气选择模式，取该模式的检出结果 |

相机没有用「框线上强梯度像素占比」，是因为近距离目标的框线恰好落在车身平滑面上，
晴天也会判成不可检出（实测 10 m 处只有 0.46）；改用框内外亮度差后判据才与「目标能否从背景里分出来」对应。

雷达阈值取 5 点，是因为 32 线雷达在 40 m 处对轿车只剩 20~30 个回波点，用 12 点会把仍可辨认的目标判成丢失。

## 运行

```bash
pip install -r requirements.txt
python main.py
```

需要先启动 CARLA 服务端（双击解压目录下的 `CarlaUE4.exe`），默认连接 `localhost:2000`。

结果写入 `results/`：

- `adaptive_metrics.csv`：每档天气的边缘密度、判别结果、所用模式与各模式检出率
- `adaptive_targets.csv`：逐距离档明细（相机对比度、回波点数、回波强度、各模式检出）
- `weather_adaptive_detection.png`：四档天气的检出叠加图（蓝框=相机检出，红点=雷达回波）
- `weather_adaptive_metrics.png`：各模式检出率、天气判别特征、逐距离对比度与回波曲线

## 注意

- 目标车可检出性判据使用真值包围盒，衡量的是「该天气下目标还剩多少可检出的结构」，
  不是完整检测器的端到端召回；这样可以把天气的影响与检测器本身的能力隔离开。
- 切换天气时必须销毁并用新的 `atmosphere_attenuation_rate` 重建雷达：该属性只能在生成时写入。
- `np.frombuffer(...).copy()` 不能省，否则回调对象释放后读到已释放内存（全 0 或原生崩溃）。
- 雷达 `stop()` 后要 `sleep(0.3)` 再 `destroy()`，否则客户端会原生崩溃。
- 脚本启动时会先清理场景中残留的车辆，并按第一个空闲出生点定位 ego；
  残留车辆会占到出生点，导致每次运行落在不同位置、数据不可复现。
