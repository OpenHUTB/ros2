具身人形机器人的物理仿真、传感器感知与平衡行走控制

对应课程任务（1）：对人形机器人/肌肉骨骼人/车辆/水下机器人/无人机进行物理仿真， 通过键盘对机器人进行运动控制； 对应课程任务（2）：实现传感器的感知及运动控制，要求使用传感器获取到的数据进行感知 （如雷达、摄像头、深度摄像头等）对机器人进行运动控制（5·2：感知、给定轨迹的控制）。 本模块面向人形机器人（具身人）。

代码位于 src/humanoid/humanoid_embodied_control/。

1. 概述与目标

本章在一台双足人形机器人上同时完成两件事：用 MuJoCo 做物理仿真并支持键盘遥控， 以及用机载传感器（激光测距 + 深度相机）感知环境后对给定轨迹做闭环行走控制。

三个必须同时成立的目标决定了本章的结构：

目标 含义 落地方式
能站住 没有控制输入时机器人不能自己倒 模型层平衡通道 + 站立姿态留屈膝余量
能听指令 键盘/轨迹指令能改变运动 参数化步态（相位 → 12 个关节目标角）
能用传感器 感知结果真的影响控制，不是数据转发 扇区可通行性 → 速度标量 + 状态机切换

1.1 与仓库中已有同类模块的区分

模块 相同点 本模块的不同点
humanoid_basics 都以 MuJoCo 为人形仿真环境 本文档只做环境配置；本模块提供完整的控制链路与代码
src/ground/mujoco_car_project 都是 MuJoCo + 键盘运动控制 对象是双足人形（平衡问题），不是轮式小车
src/water/rov_mujoco 都有 MuJoCo 仿真与 ROS 封装 对象是水下 6-DOF，不存在"单腿支撑"这类平衡约束
src/air/uav_physical_simulation 都是"物理仿真 + 键盘控制"作业 无人机是全驱动六自由度；人形是欠驱动，必须靠落脚与平衡
src/air/uav_perception_trajectory 都是"感知 + 给定轨迹跟踪" 无人机用点云直方图 + PID；人形要额外解决支撑面与竖直高度

配置步骤不重复（老师评审要求）

Miniconda / MuJoCo 的安装、环境激活、图形库依赖等通用配置步骤， 请直接参考 人形机器人基础「配置 Miniconda 和 MuJoCo 物理仿真环境教程」。 本文档只描述本模块特有的内容（模型设计、控制算法、参数整定与实测结果）。

3. 算法流程

sim 模式（在线，需 MuJoCo）：
  加载 models/humanoid.xml → 站立（根力矩 + 关节角指令）
  → 每 10 ms（100 Hz）：
      每 50 ms 更新感知：
        mj_ray 扫 96 条射线 → 16 扇区可通行性
        → 中心 9 条射线派生深度可通行比例
        → 加权融合
      状态机(前向净空, 到目标距离) → 速度标量 v、转向偏置
      相位 φ += rate(v)·Δt → 12 个关节目标角
      根节点 6 个广义力（姿态 PD + 高度保持）
      写 ctrl[0:6]（力矩）+ ctrl[6:18]（目标角） → mj_step
  → 到目标 / 堵塞 / 摔倒 则结束，输出指标 JSON

offline 模式（无 MuJoCo）：
  同一套感知/步态/状态机
  用解析障碍模型 + 平面运动学积分代替物理引擎
  → 验证控制链路，不声称验证平衡

teleop 模式（任务 1）：
  物理仿真 + 键盘（W/S/A/D/Q/E/空格/ESC）
  → 与 sim 共用同一份平衡与步态代码

4. 源码解析

4.1 models/humanoid.xml — MuJoCo 人形模型

项 数值 / 说明
自由度 nq=19（freejoint 7 + 12 个关节），nv=18
执行器 nu=18：6 个平衡通道 + 12 个关节位置伺服
时间步 0.5 ms（伺服刚度较高，≥1 ms 会数值爆炸）
质量 总 22.7 kg，躯干 11.6 kg，腿 7.1 kg
腿长 大腿 0.34 m + 小腿 0.34 m，站立屈膝 0.30 rad 时躯干高 0.946 m
传感器 framequat（姿态）、gyro、accelerometer、双脚 touch

拓扑：串链必须写成 thigh(髋) → thigh_link(膝,偏移=大腿长) → shank_link(踝,偏移=小腿长) → 脚掌几何。 MuJoCo 的 body pos 是相对父 body 的静止偏移、关节旋转整棵子树， 写成"三个 body 各偏移 -0.34"才是运动学链。

平衡执行器：torso 已挂 freejoint，不能再加 hinge（会触发 more than 6 dofs in body）；tendon 刚度只能表达"沿关节轴的位移弹簧"。 因此用 6 个 <general> 执行器把标量 ctrl 乘 gear 作用到根节点 6 个自由度：

<general name="balance_roll"  tendon="root_x" gear="1" ctrlrange="-300 300"/>

它们承载的是控制器算出的恢复力矩，不是模型里写死的常数——可调、可审计。

BalanceController.joint_command 12 个目标角 → 速率限制后的 ctrl 指令
ankle_correction / apply_ankle_strategy 踝/髋策略补偿（符号实测标定）
is_fallen(quat, z) 摔倒判据：高度 < 0.55 m 或 倾角 > 70°

4.5 scripts/main.py — 三模式主入口

类 / 函数 作用

5.9 常见问题

Q1：ModuleNotFoundError: No module named 'mujoco'？ 装依赖（5.3 节）。只想验证算法用 --mode offline（不需要 MuJoCo）。

Q2：机器人第一帧就被弹飞 / QACC 出现 NaN？

先查 ctrl 的语义。本模型的 12 个关节是 <position> 执行器，ctrl 是目标角。 把力矩（数百 N·m）填进去，等效于要求关节转到几百弧度，位置伺服瞬间饱和。 下行契约必须是"根节点收力矩、关节收角度"（见 BalanceController.joint_command）。

Q3：站立时躯干慢慢下沉，最后坐到地上？

站立构型不能完全伸直。大腿/小腿各 0.34 m，与躯干到脚的落差相等， 站立处在运动学奇异点——实测 knee_cmd=0.05 就让躯干下降 0.58 m。 stand_pose() 默认 knee_bias=0.30，不要改成 0。

Q4：行走走了十几步就倒 / 单腿支撑时倾倒？

先看步态更新频率。20 Hz 的步态更新会让"摆动相开始"出现半个周期的跳变， 机器人被自己的目标阶跃踢翻。main.py 里 gait_every 是 100 Hz； ROS 节点的 ctrl_hz 同理不要低于 100。

Q5：把 period 调大就想走慢一点，结果反而倒了？

phase_rate 不设 1/period 上限是有原因的：0.77 cycle/s 会因 单腿支撑过久而摔倒，本模型需要约 3.85 cycle/s 的踏步频率。 "走得慢"要靠减小 speed_max，不是拉长周期。详见 6.3 节。

Q6：IMU 读出来永远是 (1,0,0,0)？

framequat 绑在 site 上，site 若没有定义朝向（缺 zaxis）， 它不跟随 body 旋转，四元数恒等。模型里已经写了 zaxis="0 0 1"， 自行改模型时不要删。

Q7：--mode sim 跑完机器人"停住不动了"？

若日志最后是 [t=..] ... FALLEN，是摔倒了（is_fallen 判据：高度 < 0.55 m 或倾角 > 70°）。 若是正常结束，会打印 "final_state": "REACHED" 或 "WALK"。 两者用 --json_out 落盘后可直接核对。

6.4 结论

  • 站立有效性：20 s 内倾角 < 0.1°、高度误差 2 mm，说明"姿态 PD + 高度保持" 的串级结构足够支撑静态平衡。
  • 行走有效性：40 s 内位移 2.79 m，躯干高度波动 < 1.5 cm、倾角峰值 6.0°， 说明"相位参数化 + 根节点平衡力"能在 MuJoCo 里产生连续行走。
  • 感知有效性：扇区可通行性直接进入速度标量与状态机切换； 离线模式的 WALK → AVOID → WALK → REACHED 迁移序列证明这条链路是通的。
  • 必须说明的边界：本实现的平衡依赖模型层 6 个 balance_* 通用执行器通道 （等价于外部扶正力），不是纯关节驱动的 ZMP 行走。因此不能把"能走" 误读成"完全仿生"。行走速度约 0.10 m/s，转向能力有限、长距离会累积航向漂移； 精确的落脚点规划（LIPM / MPC）与零力矩点约束留给后续工作。
