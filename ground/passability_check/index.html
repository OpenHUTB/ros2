车辆几何通过性核算（接近角 / 离去角 / 纵向通过角）

「这台车能不能下这个地库」「过这个减速带会不会拖底」——平时只能看参数表里的接近角、离去角， 或者干脆开过去听声音。这一页把这件事做成可计算、可断言、可回归的三个角度加一条剖面。

实现放在 src/ground/passability_check/，纯标准库，不需要 CARLA、不需要 MuJoCo、不需要 GPU 与显示器， 一条命令在终端出结果。

1 这一页解决什么问题

车位、坡道这类场景，卡人的不是「马力不够」，而是几个纯几何的量：

  • 下坡道底部的下凹折角卡接近角。车头最前点在折线上一沉，前唇就蹭了——这是地库最常见的刮蹭。
  • 坡顶转平的上凸折角卡纵向通过角。车身中部骑在折点上，地板先碰地——山路、厂区坡道最典型。
  • 减速带高 10 cm、坡面只有 35 cm。它比前悬还短，用「无限长斜面」判据会判得过严， 必须按真实剖面逐位姿算。

所以本页给了两套判据，并且明确谁说了算：

判据 依据 用途
角度判据 车辆几何 + 剖面折角 横向比较车型，和参数表上的数字对得上
数值判据 沿剖面逐位姿采样车身下缘 回答「这一条剖面到底蹭不蹭」，以它为准

两者不一致时，结论取 PASS_WITH_NOTE 并打印一条 备注 说明原因（见第 6 节的减速带那两行）。 三档结论的含义：

result 含义 依据
PASSED 五条断言全过 角度与数值一致
PASS_WITH_NOTE 数值复核能过，角度判据不通过 数值判据为准；备注说明为什么角度判据偏保守
FAILED 数值判据不通过（托底或余量不足） 数值判据为准

早期版本用「五条断言全过」当结论，于是减速带那组会出现「结论 FAILED、备注说以数值复核为准」 的自相矛盾——下游只要读 result 就会把「能过」当成「过不去」。现在结论字段只由数值判据决定， 角度判据降级为 PASS_WITH_NOTE + 备注，两者不会再打架。

2 三个角度怎么算

一律以后轴接地点为原点，x 向前、z 向上，单位米。L 轴距，fo 前悬，ro 后悬， hf / hm / hr 分别是车头、车底最低点、车尾的离地高度，最低点在轴距的 k 处（默认 k = 0.5）：

量 公式 轿车默认 SUV 默认
接近角 atan2(hf, fo) 9.04° 14.51°
离去角 atan2(hr, ro) 11.89° 16.93°
纵向通过角 atan2(hm, kL) + atan2(hm, (1-k)L) 11.84° 17.10°

k = 0.5 时纵向通过角退化为教科书里的 2·atan(2hm / L)，两者的数值在测试里逐位比对过 （C10）。注意一个反直觉的结论：车底最低点越靠中间，纵向通过角越小——两条切线同时变平， 这是最不利的位置；把最低点挪到 k = 0.35，同一台车的纵向通过角从 11.84° 变成 12.99°（C11）。

3 为什么还要数值复核

接近角、离去角、纵向通过角对应的是无限长斜面：坡要一直延伸下去，车头才会「沉到底」。 真实坡道有长度。减速带的坡面只有 0.35 m，而前悬 0.85 m——车头还没完全爬上坡面， 前轮已经下坡了，所以按角度算会判「过不去」，实际能过。

数值复核的做法是：让车沿剖面走一遍，每个位姿都把车身下缘的 41 个采样点变换到世界坐标， 和路面高度比较，记下最大侵入量（> 0 就是托底）和它发生的位置。俯仰角由前后两个接地点确定—— 给定后轴位置，用二分求出前轴接地位置，使两接地点弦长正好等于轴距。

4 五条断言

断言 判据 不通过意味着
接近角 接近角 >= 剖面最大下凹折角 下坡道、进沟时前唇先碰地
离去角 离去角 >= 剖面最大下凹折角 倒车出坡时后保险杠先碰地
纵向通过角 纵向通过角 >= 剖面最大上凸折角 过坡顶、上陡坡转平时地板先碰地
离地间隙 最低离地 >= 场景门槛 + 安全余量 减速带、门槛、积雪把车底顶起来
全程不托底 扫描最小余量 >= 安全余量 逐位姿采样后确实蹭到了，报告给出位置与深度

前三条的「需要多少度」由剖面折角自动算出，不用手填；后两条由场景文件的 min_clearance_m / safety_margin_m 给出。五条互相独立，失败信息都带「差多少」。

terrain 是 x 严格递增的折线（米），两端按水平延长；min_clearance_m 是「本场景最低要留多少离地」 （减速带、门槛、积雪），safety_margin_m 是额外的安全余量。用 JSON 而不是 YAML， 是因为 json 是标准库，跑测试的机器上不需要额外装 PyYAML。

换自己的坡道只要改 terrain：折点写坡底、坡顶、平段端点即可，折角由程序自己算。

11 常见问题

接近角是不是 atan(离地/前悬) 这么简单？ 是。接近角定义就是「前轮接地点到车头最低点的连线」与地面的夹角，两点坐标分别是 (0, 0) 和 (fo, hf)，所以 atan2(hf, fo)。前提是车头最低点就在最前缘；如果保险杠下方有个更高的唇边， 把 hf 换成那个唇边的高度即可。

为什么纵向通过角用两个 atan 相加，而不是 2·atan(2hm/L)？ 后者只在车底最低点正好在轴距中点时成立。真车最低点常常偏前（发动机下护板）或偏后， 用两个 atan 相加才是通式；k = 0.5 时两者数值完全一致，测试 C10 逐位比对过。

扫描步长 0.029 m 够细吗？ 够。侵入量是位置的光滑函数，步长减半（--steps 960 --samples 81）后最大侵入量只在小数点后 第三位变化（F17/F18 覆盖这一点）。

为什么只算二维剖面？左右轮不一样高怎么办？ 单侧车轮上台阶是横向不对称工况，需要三维建模（四个轮子的接地约束），不在本模块范围内。 本模块处理的是「整车沿一条纵向剖面通过」，也就是地库坡道、减速带、坡顶这些最常见的情形。

满载后车身下沉，结果还准吗？ 本模块不含悬架压缩，clearance_* 填的是静态值。满载时离地高度会减小，把三个 clearance_* 换成满载实测值再算一遍即可——角度和侵入量都会跟着变。
