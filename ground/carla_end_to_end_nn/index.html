CARLA 端到端神经网络（图像 → 控制）

对应课程作业四：端到端模型——输入相机图像、直接输出控制指令， 中间不再有"感知目标 → 解析规划 → 控制"的人工分层。

1. 概述与目标

本模块在 自动驾驶代理 示例的基础上做拓展：已有示例用规则式方式 沿路径点行驶，本模块把整条链路替换为一个可训练的卷积神经网络：

代码位于 src/ground/carla_end_to_end_nn/。

2. 计算原理

2.1 端到端学习的思想

传统自动驾驶分三个模块：感知（识别车道线/障碍）→ 规划（算路径）→ 控制（算转向）。 端到端把这三级合成一个函数，直接从像素映射到控制量：

参数 通过行为克隆（behavioral cloning）从专家驾驶数据中学得—— 这也是 NVIDIA 在 2016 年 "End to End Learning for Self-Driving Cars" 中采用的思路。

2.2 卷积神经网络结构

各层含义：

  • 卷积层：提取局部空间特征（车道线边缘、方向、曲率），权重共享使参数量与图像尺寸解耦。
  • ReLU：，提供非线性，缓解梯度消失。
  • 最大池化： 窗口取最大值，提供平移不变性并降维。
  • 全局平均池化：把每个通道的特征图压成一个数，避免全连接层的参数爆炸。
  • tanh 输出层：把结果压到 ，与 CARLA 的 steer 值域一致。

2.6 留出集评估与数据增强的覆盖范围

端到端模型最容易自我欺骗的地方是评估口径：训练集上的 MAE 只说明"网络背下了 这 112 张图"，不说明"换一批同分布的图像还能开"。因此训练前先把数据切成互不重叠的 训练 / 留出两部分（split_dataset，固定 seed 可复现），留出集不参与任何梯度更新， 指标按两个口径分别报。这才是"能泛化"的证据。

只看干净留出集还会漏掉另一件事：输入分布会变。真实部署时相机自动曝光、隧道口、 夜雨都会改变亮度与信噪比，而图像一变，网络输入就偏离了训练分布。用与标签无关的 光度偏移把这种偏移量化出来：

亮度与噪声不改变"路往哪弯"，所以标签不用改——这正是它适合做偏移诊断的原因。

数据增强就是把这个偏移"预演"进训练集。但这里有个反直觉的结论（实测见 §6.3）：

  • 增强范围必须覆盖部署时的偏移强度，否则不但没有收益，在强偏移下还会更差；
  • 窄范围（增益 0.85~1.15、σ=3）只学到了"轻微曝光差异"，遇到 ×0.6 的暗光输入反而 比不增强更糟（0.326 vs 0.283）；
  • 宽范围（增益 0.45~1.45、σ=12）把强偏移下的 MAE 从 0.283 压到 0.132，代价是干净集 上略降（0.058 → 0.081）。

刻意不做横向平移 / 裁剪：平移会改变车道线相对车体的位置，"正确转向"随之改变， 标签不跟着改就破坏了图像与标签的因果关系。水平镜像则必须同时把标签取负 （左弯变右弯），这是唯一被允许的几何增强。

3. 算法流程

collect（需 CARLA）——行为克隆采集：
  循环 frames 次：
    world.tick()                      推进场景与相机
    读当前相机图像 + 车辆位姿
    用地图路点 API 前视 → 专家纯跟踪转向

    把专家转向应用到车辆

  读数据集 → 归一化到 [0,1]
  → CNN 前向（conv→relu→pool→conv→relu→pool→GAP→FC→tanh）

  → 保存模型 JSON

test（需 CARLA）：
  加载 CNN → 循环：tick → 取图像 → CNN 推理 steer → 应用到车辆

  合成道路图像（车道线弯曲量 = 标签）
  → 切出留出集 → 训练 CNN（可选数据增强）
  → 训练集 / 留出集两套指标
  → 导出损失曲线、预测对比曲线、样本图像
  → 可选 --ablation：基线 / 复制扩容 / 增强 × 三档光度偏移

5.11 常见问题

Q1：训练后损失不下降、方向判对率约 50%？ 先检查两点：(a) 数据集里的图像与标签是否有因果关系——若标签是人为信号 （如正弦），网络学不到任何东西，必须改用行为克隆采集； (b) maxpool 反向传播是否按 argmax 回传。可用 python3 test/test_end_to_end_logic.py 回归验证这两点。

Q2：MAE 出现几十甚至十几的数值？ 这是推理时遗漏 tanh 的典型症状——转向值域应在 ，MAE 不可能大于 2。 检查 predict() 与训练是否使用同一输出激活。

Q3：--mode collect/test 报"缺少 carla 模块"？ 需安装 CARLA 0.9.16 的 Python 客户端 wheel，见 5.3 节。 只想验证算法可改用 --headless --demo（不需要 CARLA）。

Q4：纯 numpy 训练太慢？ 端到端 CNN 为纯 numpy 实现（无 GPU 加速），训练时间与样本量成正比。 可减小 --samples，或改用 --backend tf（需自行安装 TensorFlow）。

Q5：合成图像上表现好，实车上不 work？ 合成图像只用于验证链路与算法正确性。真实场景必须用 5.7 节的行为克隆采集 （或使用 CARLA 公开数据集）训练，并注意训练/测试的图像分布一致性。 这一条现在可以量化：用 photometric_shift() 把留出集压暗到 ×0.6 并加 σ=18 噪声， 基线模型的 MAE 会从 0.058 涨到 0.243（退化 4.2×）；启用宽范围光度增强后压到 0.092 （退化 0.9×），见 6.3 节。实车部署前建议先跑一遍这个偏移诊断。

Q6：明明做了增强，干净集指标却变差了？ 这是预期行为，不是 bug。增强换来的不是理想光照下的精度，而是光照/噪声变化下的 鲁棒性：本机实测 clean 上 aug 0.099 劣于 base 0.058，但 mild/strong 偏移下反超 4.3× / 2.6×。若部署现场曝光可控，可以不加增强；不可控时应加，且范围要覆盖现场 偏移强度（窄范围增强在强偏移下比不增强还差）。

配置 训练样本 clean mild strong 强偏移退化倍数
base（不增强） 112 0.05836 0.14047 0.24349 4.2×

aug（镜像 + 宽范围光度增强） 224 0.09883 0.03241 0.09236 0.9×

三条结论都反直觉，值得记下来：

  1. 干净集上增强反而更差（0.099 vs 0.058）。若只看干净指标，会误判"增强没用"， 甚至据此删掉它——这是本页最容易被误读的一张表。
  2. "仅复制扩容"帮不上忙（0.087/0.170/0.336，各档都劣于基线）。数据量翻倍而信息 不变时，多出来的只是重复梯度步；把它的功劳记到"增强"头上是常见归因错误。
  3. 增强的收益全部体现在输入分布变化时：强偏移下 0.243 → 0.092（降低 2.6 倍）， 退化倍数从 4.2× 压到 0.9×。而且增强范围必须覆盖部署偏移——早期用窄范围 （增益 0.85~1.15、σ=3）时，强偏移下为 0.326，比不增强还差。

代价也要讲清楚：aug 在干净集上比 base 差 0.04（MAE），即用一点理想光照下的精度 换取暗光/噪声下的鲁棒性。工程上怎么选，取决于部署现场的曝光条件是否可控。

6.5 结论

  • 端到端可行：单个 CNN 仅凭 的相机图像即可输出转向， 留出集方向判对率 100%、相关系数 +0.993，验证了"像素 → 控制"的直接映射可以被学到。
  • 泛化可测：留出集 MAE 0.0584 与训练集 0.0572 基本一致，说明不是靠背样本； 但干净集指标不足以说明鲁棒性——同一模型在光度偏移下退化 4.2×。
  • 增强是鲁棒性手段，不是精度手段：宽范围光度增强把偏移退化从 4.2× 压到 0.9×， 代价是干净集精度略降（0.058 → 0.099）；窄范围增强在强偏移下反而更差， 说明增强覆盖范围必须匹配部署偏移，不能"随便加一点"。
  • 无分层：推理路径中不存在任何人工的感知/规划环节，转向完全由网络权重决定。
  • 与逐层方案对比：作业二/三采用"感知 NN + 控制 NN"的分层方案， 可解释性强、易调试；本模块端到端方案链路最短、不依赖人工特征， 但可解释性弱、对数据分布敏感，两者是工程上的取舍。
