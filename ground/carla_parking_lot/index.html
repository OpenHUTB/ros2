CARLA 停车场场景生成

概述

在 CARLA 0.9.16 仿真器的 Town04 地图中，通过 Python API 自动生成一个带车位线的停车场场景，包含 6 个垂直停车位，并自动将镜头移动到停车场上方俯视。

环境要求

  • CARLA 0.9.16（服务端运行于 Windows 有 GPU 的宿主机）
  • Ubuntu 22.04 + ROS 2 Humble + Python 3.10（运行客户端脚本）
  • Python 依赖：carla==0.9.16

安装步骤

1. 下载安装 Windows 版 CARLA

从官方 Release 页面下载 CARLA 0.9.16 Windows 版： https://github.com/carla-simulator/carla/releases/tag/0.9.16

下载 CARLA_0.9.16.zip，解压到任意目录（记为 CARLA 安装目录）。

2. 启动 CARLA 服务端

进入 CARLA 安装目录后运行： 

CarlaUE4.exe -quality-level=Low

3. 配置 Windows 防火墙

在 Windows Defender 防火墙中添加入站规则，放行 TCP 2000 和 UDP 2000 端口。

4. 获取代码并编译 ROS2 包

在 Ubuntu 客户端创建工作空间，并将仓库克隆到 src 目录：

mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src
git clone https://github.com/OpenHUTB/ros2.git

然后编译停车场模块：

cd ~/ros2_ws
colcon build --packages-select carla_parking_lot
source install/setup.bash

运行

# 默认连接 192.168.43.1:2000
ros2 launch carla_parking_lot parking_lot.launch.py

# 指定 CARLA 服务器 IP
ros2 launch carla_parking_lot parking_lot.launch.py host:=192.168.1.100

运行效果

  • 自动切换到 Town04 地图
  • 在停车场位置绘制 6 个绿色车位线框
  • 标注 P1-P6 车位编号
  • 镜头自动跳到停车场上方俯视

技术说明

  • 使用 world.debug.draw_line() 绘制车位边界线
  • 使用 world.debug.draw_string() 标注车位编号
  • 使用 world.get_spectator() 获取并移动镜头
  • 车位坐标通过在 CARLA 窗口中飞镜头手动读取获得

自主实现：不依赖 CARLA 的倒车入库规划器

上面的流程门槛不低：要一台有 GPU 的 Windows 机器跑 CARLA 服务端，要 Ubuntu 22.04 + ROS 2 Humble + Python 3.10 跑客户端，还要放行 2000 端口。如果只是想回答「这台车能不能 停进这个车位、会不会蹭到旁边的车、要倒多少米」这类问题，其实不需要整个仿真器。

src/ground/reverse_parking_planner 就是把这部分只跟几何有关的逻辑单独拿出来做成了 一个 ROS 1 包：给定车位尺寸、车辆几何和转弯半径，算出一次倒车入库的完整路径，在终端 打印断言结果和字符俯视图，并把路径发布成 nav_msgs/Path。它不订阅任何话题，不依赖 CARLA，也没有图形界面，roslaunch 一跑就能出结果。

目录结构

src/ground/reverse_parking_planner/
├── CMakeLists.txt
├── package.xml
├── README.md
├── config/parking_planner.yaml
├── launch/main.launch
└── scripts/
    ├── main.py                  # 入口
    ├── parking_planner_node.py  # 读参数、算路径、发消息
    └── parking_core.py          # 几何核心（纯标准库，可离线测）

路径怎么算出来

全程倒车，所以路径只有两段，长度恒为 R·pi/2 + entry_length：

  1. 目标位姿 T 在车位正中，车头朝向车道 —— 倒车入库停好之后车头是朝外的；
  2. 倒车行驶方向与车头相反，从 T 沿行驶方向反向退 entry_length 米得到 J， 此时车头已经对准车位，只剩最后一小段直线；
  3. 圆心 C 取在 J 行车方向的右侧 turn_radius 米处，起点 S = C − R·travel；
  4. 圆弧从 S 右转 90° 到 J，再从 J 倒车 entry_length 米到 T。

规划前会先校验 turn_radius 是否小于车辆最小转弯半径 wheelbase / tan(max_steer)（默认 2.70 / tan(0.55) ≈ 4.40 m）。小于就直接抛 ParkingError，不会给出一个物理上开不出来的路径。

默认参数下的关键量：路径长 5·π/2 + 3 = 10.854 m，转角 90°，起点 (5.000, −5.750)， 终点 (0.000, 2.250)，采样 110 个点。

常见问题

  • ParkingError: 转弯半径 3.000 m 小于车辆最小转弯半径 4.404 m plan/turn_radius 比车能转的最小半径还小。调大 turn_radius，或调大 vehicle/max_steer（例如 0.70）。
  • [FAIL] 无碰撞 车位太窄或直线段太短，车身切入时会碰到邻车。加大 slot_width 或 entry_length。
  • Melodic 上日志里出现 UnicodeEncodeError 给 rospy 打非 ASCII 日志必须传 byte str，节点里已用 _log() 统一转换；如果你在别的 节点里自己写 rospy.loginfo("中文 %s", x)，在 Python 2.7 下会踩同样的坑。
