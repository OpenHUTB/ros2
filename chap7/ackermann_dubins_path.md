# Dubins 最短路径：车轮不能横着走，最短路线就变了

前几章讲到的 RRT、A\* 都假设机器人可以原地转向。但第 7 章的阿克曼小车做不到：
它的前轮最多打到一个固定角度，后轮永远沿着车头方向滚动。这就带来一条硬约束
——**路径的曲率不能超过 `1/R`**，`R` 是最小转弯半径。

约束一加，「两点之间直线最短」立刻失效。下图是同一辆小车从 `(0,0)` 出发、
分别以 90° 和 180° 的终点朝向到达 `x=10 m` 的两条最短路径：

![两种工况下的 Dubins 最短路径](../img/chap7/ackermann_dubins_path/dubins_cases.png)

蓝线（换向 90°）要 10.63 m，红线（掉头 180°）要 13.34 m——都比直线 10 m 长。
多出来的部分是「把车头拧过来」的代价，而且这个代价不能省。

## 1. Dubins 定理：最优解必是六种形状之一

1957 年 Dubins 证明：在只允许前进、曲率有上界的条件下，两点位姿之间的最短路径
一定由「圆弧」和「直线」拼接而成，且**最多三段**。按转向的组合，只有六种：

| 情形 | 组成 | 什么时候赢 |
|---|---|---|
| LSL | 左转 - 直线 - 左转 | 终点朝向相对起点「向左」偏 |
| RSR | 右转 - 直线 - 右转 | 终点朝向相对起点「向右」偏 |
| LSR | 左转 - 直线 - 右转 | 需要一次反向修正（如 U 形掉头） |
| RSL | 右转 - 直线 - 左转 | 与 LSR 镜像 |
| RLR | 右 - 左 - 右 | 位置几乎不动、只把车头转过来 |
| LRL | 左 - 右 - 左 | 与 RLR 镜像 |

六种情形各算一个候选，取最短的那个就是全局最优。所以「求最短」这个连续优化
问题，被压缩成了「算 6 个闭式解」——这就是 Dubins 路径在工程里好用的原因。

## 2. 怎么算：几何构造 + 端点闭环校验

教材里的六个闭式公式都写成 `atan2` 加一堆三角项，抄错一个符号很难发现。
本模块换了个做法：**直接做几何构造，再用端点校验筛掉错的分支**。

以「弧 - 直线 - 弧」为例：

1. 起点按第一个字母（L 或 R）确定圆心 $C_1$，终点按第三个字母确定 $C_3$；
2. 同向转（LSL / RSR）求两圆的**外公切线**，长度就是圆心距；
   反向转（LSR / RSL）求**内公切线**，长度是 $\sqrt{D^2 - 4R^2}$，需要 $D \ge 2R$；
3. 由切线方向反推第一段和第三段的转角；
4. **把三段长度积分回去，检查是否精确落在目标位姿上**——不满足就直接丢弃。

第 4 步是关键。几何分支往往有两条（内外公切线各一），其中一条是伪解；
用端点闭环卡一遍，错的分支自己就出局了，不用去记「哪个公式配哪个符号」。

「弧 - 弧 - 弧」（RLR / LRL）同理：中间那个圆必须同时与两端圆外切，圆心就是
两个「半径 2R 的圆」的交点，两个交点各试一次。

实测精度：端点位置误差 $< 10^{-15}$ m、朝向误差为 0——只差浮点舍入。

## 3. 结果

四个工况（`R = 1 m`）：

| 工况 | 最优情形 | 长度 | 次优解 | 相比省下 |
|---|---|---|---|---|
| `(0,0,0)` → `(10,0,0)` 同向 | LSL | 10.0000 m | 10.0000 m | 0% |
| `(0,0,0)` → `(10,0,90°)` | RSL | 10.6266 m | 15.7580 m | **32.6%** |
| `(0,0,0)` → `(10,0,180°)` | LSR | 13.3423 m | 13.3423 m | 0% |
| `(0,0,0)` → `(6,4,-90°)` | LSR | 8.8291 m | 12.3282 m | **28.4%** |

「同向」那条退化成直线（10 m），符合直觉。「换向 90°」和「斜向换向」两条，
最优点比次优点省 30% 左右——这就是「选对情形」的价值：同样叫 Dubins 路径，
选错形状就要多绕三成。

「掉头 180°」里有意思的一点：LSR 和 RSL 给出**完全相等**的 13.3423 m。
这不是巧合，两个解互为镜像（把整个场景沿 `x` 轴翻过来，左右转向互换，长度不变）。
`tests/test_dubins.py` 里专门有一条断言守着这个对称性。

固定起终点位置（相距 10 m）、只改终点朝向，最短长度画出来是一条 U 形：

![最短长度随终点朝向的变化](../img/chap7/ackermann_dubins_path/dubins_length_vs_heading.png)

两端（朝向差 180°，即原地掉头）最长 13.34 m，中间（朝向一致）最短 10.00 m。
形状左右对称，也正是上面那条镜像对称性的体现。

最小转弯半径本身的影响：

![同一掉头工况下不同转弯半径的路径](../img/chap7/ackermann_dubins_path/dubins_radius_effect.png)

`R` 从 1 m 放到 3 m，同一个掉头的长度从 13.3 m 涨到 21.3 m。**转弯半径越大，
兜的圈子越大**——这条看起来很朴素，但它解释了为什么配送小车在窄巷里要把车身做小。

## 4. 代码与运行

```bash
cd src/chap7/ackermann_dubins_path
python3 tests/test_dubins.py   # 19 项单元测试
python3 scripts/main.py        # 打印工况表并重新生成 3 张图
```

`scripts/dubins.py` 里三个入口：

| 函数 | 作用 |
|---|---|
| `dubins_path(start, goal, R)` | 返回最短那一类 `DubinsPath` |
| `all_paths(start, goal, R)` | 返回全部可行候选（按长度升序），可看「谁输谁赢」 |
| `DubinsPath.sample(step)` | 按弧长等间隔取 `(x, y, theta, kappa)` |

```bash
colcon build --packages-select ackermann_dubins_path
source install/setup.bash
ros2 launch ackermann_dubins_path ackermann_dubins_path.launch.py
ros2 topic echo /dubins/path --once
```

```bash
ros2 launch ackermann_dubins_path ackermann_dubins_path.launch.py \
    goal_yaw:=1.5708 radius:=2.0
```

## 5. 局限与延伸

- **只考虑前进**。允许倒车时叫 Reeds-Shepp 曲线，形状更多（也包含倒车直线段），
  掉头长度能明显缩短。
- **只处理二维平面、匀速**。真正的车还有加速度约束，得把速度剖面叠上去——
  这正是本仓库「梯形与 S 曲线速度规划」那篇做的事。
- **不考虑障碍**。Dubins 只解决「两个位姿之间怎么走最短」，绕障需要在更高一层
  做搜索（比如在 `(x, y, theta)` 上做 Hybrid A\*，用 Dubins 当启发式和边扩展）。
- 本实现对每个几何分支都做端点校验，代价是常数变大概 2 倍；在毫秒级预算下
  完全无所谓，但高频重规划（>1 kHz）时值得改成纯闭式。

## 6. 与已有内容的关系

- 与「RRT 采样式路径规划」互补：RRT 不关心曲率，适合全向移动机器人；
  Dubins 必须满足曲率，适合阿克曼车。两者可以串起来——先用 RRT 找到粗略路点，
  再用 Dubins 把相邻路点连成可执行的曲线。
- 与「Stanley 前视路径跟踪」衔接：Dubins 给出一条**车能走**的路径，
  Stanley（或下一篇的 MPC）负责把它跟住。
- 与「阿克曼 MPC 轨迹跟踪」是同一条链路上的前后两步：本文生成路径，那篇跟踪路径。
